# 001 携帯の通信速度は、街の様子から予測できるか

東京 23 区の携帯の下り速度を、人口、建物、POI、街路の様子、基地局から予測しようとした実験 (003-A から 003-E) を、データサイエンティストの作業の順に並べ直したもの。結論は「予測の信号が弱く、複雑なモデルを採用する根拠が無い」。数字は各実験の README から引いた (2026-09-29 に回したもの)。このリポジトリでまだ行っていない作業は「未実施」と書いた。

## 1. 問題設定: 何のために予測するのか

- 想定した使い道: 測定の無い場所の速度を、街の様子から推定する。速度の遅い場所を見つけ、基地局を足す候補を絞る材料にする。
- 予測する値: Ookla の携帯のタイル (ズーム 16、約 610m 四方) の下りの平均速度の対数。23 区の 2,246 タイル、中央値 93Mbps。
- 点数: 測定回数で重み付けした R²。1 回しか測っていないタイルの平均は、それだけで揺れるため。
- 台東区は 62 タイルしかなく、この問題は 23 区が主 ([docs/setup.md](../../docs/setup.md))。

## 2. データの確認

- Ookla Speedtest ([docs/datasets/ookla-speedtest](../../docs/datasets/ookla-speedtest/README.md)): タイルごとの測定回数がばらばら。23 区で 1 回だけのタイルが 16%、10 回以上は 34%。ライセンスは CC BY-NC-SA 4.0 (非営利)。
- OpenCelliD ([docs/datasets/opencellid](../../docs/datasets/opencellid/README.md)): 23 区のセルは 86,795 件 (LTE 77,215、UMTS 8,687、NR 893)。位置は利用者の観測からの推定で、基地局の実際の位置ではない。事業者は分けていない。
- 周辺環境の特徴量 (`study_geoai.features.tiles`): WorldPop の人口、Overture の建物の面積の割合と数、POI の数、みちよみの無電柱化の割合、見える電柱、緑の割合。
- 分かったこと: 速度を決めるはずのもの (どの事業者の、どの局に、どれだけの人がつないでいるか、測った時間帯、端末) は、どのデータにも無い。

## 3. ベースライン

- 全体平均: 予測を 23 区の平均にすると、R² は定義から 0。以下のモデルはこれと比べる。
- 前四半期 ([003-C](../../src/003-C-noise-ceiling/README.md)): 同じタイルの前の四半期の速度で予測すると、R² 0.15 (四半期の間の全体のずれを直線で除いたもの)。測定 100 回以上のタイルに限ると 0.8 前後。これが「その場所そのもの」で説明できる量の目安 (雑音の天井) になった。
- 地域平均 (区の平均で予測する): 未実施。

## 4. 評価の設計

- ランダムな分割: 5 分割の予測をまとめて 1 回で採点した ([003-A](../../src/003-A-gradient-boosting/README.md))。分割の切り方 (乱数の種) を 5 通り変えると、点数は標準偏差で 0.01 から 0.05 動き、モデルの間の差と同じくらいだった ([003-E](../../src/003-E-pooled-target/README.md))。
- 空間ブロック CV: この問題では未実施。ほかの問題 (無電柱化と人口密度) では、台東区で点数がはっきり下がることを [004-A](../../src/004-A-cross-validation/README.md) で確かめている。速度はランダム分割でもほとんど予測できないので、空間で分ければさらに下がると考えられるが、確かめていない。
- 時間で分ける (前の四半期で学習し、次の四半期で試す): 未実施。

## 5. モデル

23 区、測定回数で重み付けした R² ([003-A](../../src/003-A-gradient-boosting/README.md)、学習にも測定回数の重み):

- 線形 0.059、ランダムフォレスト 0.055、scikit-learn の HistGradientBoosting 0.095、XGBoost 0.068、LightGBM -0.009、CatBoost 0.081。
- どれも 0.1 に届かない。ブースティングの 4 つの差は、この程度の信号では意味のある差ではない。
- 台東区 (62 タイル) では、どのモデルも R² がマイナス。
- XGBoost の性質 (学習率、深さ、早期打ち切り) は、信号のある無電柱化の問題で見た ([003-B](../../src/003-B-xgboost/README.md))。

## 6. 誤差の分析

- 雑音の大きさ: 測定回数の多いタイルほど四半期をまたいでよく一致する ([003-C](../../src/003-C-noise-ceiling/README.md))。誤差の大半は、モデルではなく目的変数の雑音から来ていると読める。
- 目的変数の作り直し ([003-E](../../src/003-E-pooled-target/README.md)): 3 つの四半期を、全体のずれを引いてから測定回数で重み付けして平均すると、CatBoost は 0.099 から 0.175 へ上がった (乱数の種 5 通りの平均。ばらつきの 3 倍ほどの差)。線形は上がらない。
- 場所ごとの誤差 (どの地域で外れるか): 未実施。
- 時期ごとの誤差: 未実施。

## 7. データを足す

- OpenCelliD の基地局をタイルごとに足した ([003-D](../../src/003-D-cell-towers/README.md))。セルの数、LTE と NR の数、事業者の数、最寄りのセルまでの距離、推定カバー範囲。
- 速度との相関は最大でも +0.19 (セルの数)。
- 足しても、ほとんど良くならない。CatBoost だけが 0.081 から 0.120 に上がり、線形 (0.059 から 0.044)、HistGradientBoosting (0.095 から -0.009)、XGBoost (0.068 から 0.010) は下がった。信号の弱い問題で列を足すと、足した列の雑音に合わせてしまう。

## 8. 結論

- 予測の信号は弱い。最も良い組み合わせ (まとめた目的変数、基地局あり、CatBoost) でも R² 0.175 で、ほとんどは説明できない。
- 大きな原因は目的変数そのもの。1 タイルの測定が少なく、同じ場所の前の四半期ですら R² 0.15 しか説明しない。
- 複雑なモデルを採用する根拠は無い。モデルの間の差は、分割の切り方による揺れと同じ大きさ。
- 次に要るのは、モデルではなく材料。事業者を分けた速度、測定の多いタイルに絞った評価、実際の基地局の位置と混み具合。
- 残っている作業: 地域平均のベースライン、空間ブロック CV と時間で分ける評価、場所と時期ごとの誤差。
