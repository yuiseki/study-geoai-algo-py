# 003-F TabPFN: 数千行で、数十万行の勾配ブースティングに近づけるか

```sh
TABPFN_ALLOW_CPU_LARGE_DATASET=1 CUDA_VISIBLE_DEVICES= \
    uv run --group tabpfn python -u src/003-F-tabpfn/run.py
```

TabPFN は、人工的に作った大量の表で事前学習した Transformer。学習データの行を入力の一部として読み、1 回の順伝播で予測する。自分の重みはデータに合わせて学習しない。「少ない行で勾配ブースティングに並ぶ」と言われるので、23 区の無電柱化 (1-B から 4-A と同じ、道の特徴 6 つ) で確かめた。数字は 2026-09-29 に回したもの (`output/run.log`)。8GB の上限で囲み、最大 2.0GB、543 秒。

- 試験: 学習に使わない 2km ブロックから取った 3,000 行 (新しい場所)。どのモデルとどの行数でも同じ行。
- 学習: ほかのブロックから無作為に 20 行から全 829,358 行まで。3,000 行までは標本を 3 通り変え、それより上は 1 通り。
- モデル: ロジスティック回帰、XGBoost、LightGBM、TabPFN v2 (10,000 行まで)。GBDT は、行の少ないときに木を浅く少なくした。
- TabPFN は CPU (32 コア) で動かした。この機械の GPU は常駐のサービスで埋まっているため。1,000 行を超えると既定では CPU での実行を拒むので、`TABPFN_ALLOW_CPU_LARGE_DATASET=1` を付けた。
- 依存は、通常の `uv sync` では入らない `tabpfn` グループにした (torch を連れてくる)。入れると torch に合わせて nvidia-nccl が 2.32.3 から 2.30.7 に下がるが、ほかのテストはすべて通った。

## 結果

AUC (標本 3 通りの平均)、括弧は学習と予測 3,000 行にかかった秒数:

- 20 行: TabPFN 0.691 (14 秒)、XGBoost 0.643、LightGBM 0.624、ロジスティック 0.641
- 60 行: TabPFN 0.776 (15 秒)、XGBoost 0.731、LightGBM 0.703
- 120 行: TabPFN 0.826 (13 秒)、XGBoost 0.789、LightGBM 0.758
- 300 行: TabPFN 0.840 (14 秒)、XGBoost 0.817、LightGBM 0.795
- 1,000 行: TabPFN 0.864 (22 秒)、XGBoost 0.829 (0.1 秒)、LightGBM 0.812
- 3,000 行: TabPFN 0.877 (44 秒)、XGBoost 0.865 (0.1 秒)、LightGBM 0.855
- 10,000 行: TabPFN 0.881 (164 秒)、XGBoost 0.872 (0.2 秒)、LightGBM 0.873
- 30,000 行: XGBoost 0.883、LightGBM 0.887 (0.2 秒)
- 100,000 行: どちらも 0.886 (0.3 から 0.4 秒)
- 300,000 行: どちらも 0.888 (0.5 から 0.7 秒)
- 全 829,358 行: XGBoost 0.890 (1.6 秒)、LightGBM 0.889 (1.2 秒)

図は `output/learning-curve.png`。

## 読み方

- 行が少ないほど TabPFN の差は大きい。120 行の TabPFN (0.826) は、1,000 行の XGBoost (0.829) とほぼ同じ。3,000 行の TabPFN (0.877) には、XGBoost は 10,000 行から 30,000 行のあいだで追いつく。
- 全 829,358 行の XGBoost (0.890) との差は、3,000 行の TabPFN で 0.013、10,000 行で 0.009。「数千行で数十万行にほぼ並ぶ」は、この問題ではおおむね当たった。ただし「ほぼ」の中身は 0.01 ほど。
- GBDT は 30,000 行から先ほとんど伸びない (0.883 から 0.890)。道の特徴が 6 つしかない問題なので、行を増やしても学べることが早く尽きる。特徴量の多い問題でも同じ差になるかは分からない。
- 標本によるばらつきも TabPFN のほうが小さい。120 行で TabPFN は 0.820 から 0.831、XGBoost は 0.767 から 0.801。
- 較正 (ECE) も行の少ないところで TabPFN が良い (1,000 行で 0.032、XGBoost 0.065)。数万行では GBDT が追いつき、追い越す (10 万行の XGBoost 0.009)。
- 速さは GBDT が桁違い。TabPFN は 10,000 行で 164 秒、XGBoost は全 829,358 行でも 1.6 秒。TabPFN の時間は行の数とともに急に伸びる (3,000 行で 44 秒、10,000 行で 164 秒)。GPU なら大きく速くなるはずだが、測っていない。
- 使いどころ: 数百から数千行しか無いときは、TabPFN が調整なしで最も良い。行が数万を超え、速さが要るなら GBDT。

## 気をつけること

- 目的変数はみちよみの VLM の読み取りで、「当たる」は「VLM の判定と合う」という意味。
- GBDT は行の数に合わせて調整していない (木の深さと本数を 3 段階に変えただけ)。調整すれば少ない行でも差が縮まる可能性がある。
