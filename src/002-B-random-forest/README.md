# 2-B ランダムフォレスト: 1 本の木、線形と比べる

```sh
uv run python src/002-B-random-forest/run.py
```

点数は、5 分割 (23 区の無電柱化は 3 分割) の予測をまとめて 1 回で測ったもの (2-A で、分割ごとの平均が 1 つの分割に振り回されたため)。ランダム分割。図は `output/`、数字は 2026-09-29 に回したもの。

## 結果

| 問題 | 行 | 線形 | 1 本の木 | 森 (葉を小さく) | 森 (葉を大きく) |
|---|---:|---:|---:|---:|---:|
| 人口密度、台東区 (R²) | 108 | 0.297 | -0.143 (深さ 5) | 0.346 (葉 1 以上) | 0.455 (葉 5 以上) |
| 人口密度、23 区 (R²) | 3,072 | 0.168 | 0.289 (深さ 5) | 0.271 (葉 1 以上) | 0.316 (葉 5 以上) |
| 無電柱化、台東区 (AUC) | 32,593 | 0.849 | 0.893 (深さ 7) | 0.926 (葉 5 以上) | 0.926 (葉 20 以上) |
| 無電柱化、23 区 (AUC) | 200,000 (標本) | 0.702 | 0.866 (深さ 11) | 0.888 (葉 20 以上) | 0.880 (葉 100 以上) |

- 森は、どの問題でも 1 本の木より良い。木を 200 本 (23 区の無電柱化は 100 本) 平均すると、1 本ずつの過学習が打ち消し合う。
- 台東区の人口密度では、1 本の木は線形に負けた (2-A) が、森は線形を超えた (0.297 から 0.455)。上野公園のような外れ値は、すべての木の標本に入るわけではないので、平均すると引っ張られ方が薄まる。
- 葉を大きくする (1 つの葉に入る行の最小数を上げる) と、行の少ない問題では良くなり、多い問題では少し悪くなった。

## 組み合わせの効果 (部分依存)

`output/pd-undergrounded-*.png` は、車道の幅と緑の割合の 2 つを動かしたときの、森の予測確率の平均 (5,000 行の標本で計算)。

- 台東区: 車道が 3.5m 以下の細い道では、緑が多いほど無電柱化済の確率が上がる (最大 0.65 ほど)。4 から 7m の道では、緑が多くてもほとんど上がらない。緑の効き方が道の幅で変わる、という関係で、線形のモデルでは表せない。
- 23 区: 車道の幅が中心。10.5 から 11.5m の帯だけが際立って高く (0.45 ほど)、緑の割合ではあまり変わらない。細い道 (3m ほど) も少し高い。

車道の幅は VLM の推定値なので、決まった数え方 (車線の数 x 3m など) で特定の幅に値が集まり、それが帯を作っている可能性もある。確かめていない。

不純度による重要度 (impurity importance) は、台東区の無電柱化で車道の幅 0.34、緑の割合 0.30、照明 0.16、色の鮮やかさ 0.15、歩道 0.03 と 0.02。値の種類が多い連続の特徴量ほど大きく出やすい (歩道の有無は 0 か 1)。重要度の測り方は 11 番で見直す。

## メモリ

はじめは 23 区の無電柱化の全 988,619 行で森を作り、プロセスの最大メモリが 16GB (616 秒) に達した。DuckDB に付けた 4GB の上限は scikit-learn には効かない。
クラスの比率を保った 20 万行の標本にし、部分依存を 5,000 行で計算するようにしたら、1.5GB (57 秒) になった。森の AUC は全体で 0.893、標本で 0.888。
