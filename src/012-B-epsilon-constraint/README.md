# 12-B ε 制約法: 重み付き和では出てこないパレート解

```sh
uv run python -u src/012-B-epsilon-constraint/run.py
```

12-A の問題で拠点の数を 13 に固定し、残る 2 つの目的 (400m 以内の人を多く、浸水ランクの和を小さく) のパレート最適な解 (どちらの目的でも同時には改善できない解) を、ε 制約法と重み付き和で求めて比べる。数字は 2026-09-29 に回したもの (`output/run.log`)。8GB の上限で囲み、最大 678MB、52 秒。

k = 13 にしたのは、12-A の重み付き和で、13 か所の解が「21.1%、浸水 0」と「48.7%、浸水 21」の 2 つしか出ず、そのあいだが空いていたから。

## 2 つの方法

- ε 制約法: 浸水ランクの和を ε 以下に制限して、覆う人を最大にする。ε を 0、1、2 と 1 ずつ上げていく。どのパレート最適な解も、ちょうどその浸水の値を ε にすれば出てくる。
- 重み付き和: `覆う人 − w × 浸水ランクの和` を最大にする。w を 0 から 20,000 まで 77 通り振った。重み付き和で出るのは、パレート最適な解の点を上から包む凸な折れ線 (凸包) の上にある点 (支持される解) だけ。

## 結果

- 浸水を気にしなければ、13 か所で 52.9% の人を覆い、浸水ランクの和は 34。
- ε 制約法は、ε = 0 から 34 までの 35 回で、34 のパレート最適な解を出した。どれも最適 (1 回あたり 0.0 から 5.4 秒)。
- 重み付き和は、77 通りの重みで 12 通りの解しか出さなかった。そのうち 11 がパレート最適な解で、34 のうち 23 は一度も出なかった。

| 浸水ランクの和 | 覆う人 | 重み付き和で出たか |
|---:|---:|---|
| 0 | 21.1% | 出た |
| 1 | 21.7% | 出ない |
| 2 | 24.7% | 出ない |
| 3 | 25.3% | 出ない |
| 4 | 28.2% | 出た |
| 5 から 9 | 28.7% から 35.1% | 出ない |
| 10 | 37.2% | 出た |
| 14 | 42.3% | 出た |
| 17 | 45.5% | 出た |
| 21 | 48.7% | 出た |
| 25 | 50.3% | 出た |
| 33 | 52.9% | 出た |

(34 すべては `output/run.log`、図は `output/front-taito.png`)

- 図では、パレート最適な解は滑らかに見える凹な曲線 (浸水を 1 つ許すごとの増え方が、だんだん小さくなる) に並ぶ。それでも、重み付き和が拾えたのは、その上側の凸包の角にある点だけ。例えば浸水 1 (21.7%) は、浸水 0 (21.1%) と浸水 2 (24.7%) を結ぶ線の中点 (22.9%) より下にあるので、どんな重みでも浸水 0 か浸水 2 に負ける。整数の問題では、曲線がわずかにへこむだけで、そこの解は重み付き和から隠れる。
- 12-A で空いていた「浸水 0 と浸水 21 のあいだ」には、実際には 20 のパレート最適な解があった。例えば浸水ランク 4 を許すだけで、覆う人は 21.1% から 28.2% に増える。
- 重み付き和は、パレート最適でない解も 1 つ返した。w = 0 のとき、浸水は目的に入らないので、覆う人が同じなら浸水がいくつでも同点になる。ソルバーは同点の中から浸水 34 の解を返したが、同じ 52.9% は浸水 33 で実現できる。重みが 0 の目的があると、重み付き和は「弱いパレート解」(ほかの解と同点の目的があり、残りで負けている) を返しうる。

## まとめ

- ε 制約法は、パレート最適な解を漏れなく出す (ε を細かく振れば)。重み付き和は凸包の上の解しか出せず、この問題では 34 のうち 23 を見落とした。
- 重み付き和で中間の解が出なかったのは、「中間の解が無い」からではなく、「重み付き和では出せない形をしていた」から。解の集合を見せて選んでもらうなら、ε 制約法で並べるほうがよい。
- 重み付き和の重みを 0 にすると、パレート最適でない解が返ることがある。
