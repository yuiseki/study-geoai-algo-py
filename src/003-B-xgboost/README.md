# 3-B XGBoost: 学習率、深さ、早期打ち切り

```sh
uv run python src/003-B-xgboost/run.py
```

3-A の携帯の速度にはほとんど信号が無かったので、信号のある無電柱化の問題 (1-B、2 番と同じ) で XGBoost を見る。数字は 2026-09-29 に回したもの (`output/run.log`、図は `output/curve-*.png`)。8GB の上限で囲み、最大メモリ 1.5GB、118 秒。

## やり方

- 学習率 (0.3、0.1、0.03) と木の深さ (3、6、9) を変える。木は最大 3,000 本。
- 本数は早期打ち切りで決める。検証の AUC が 50 本続けて伸びなければ止める。検証用のデータは、各分割の学習側から 2 割を取り分けたもの。テスト側を見て本数を決めると、テストの情報が漏れる。
- 点数は 5 分割 (ランダム) の予測をまとめた AUC。23 区は、クラスの比率を保った 20 万行の標本。

## 結果

| | 台東区 (32,593 行) | 23 区 (20 万行の標本) |
|---|---:|---:|
| XGBoost の最良 | 0.930 | 0.894 |
| ランダムフォレスト (2-B) | 0.926 | 0.888 |
| 1 本の木 (2-B) | 0.893 | 0.866 |
| ロジスティック回帰 (1-B) | 0.849 | 0.702 |

XGBoost は森をわずかに上回ったが、差は 0.004 から 0.006。

台東区の、早期打ち切りで選ばれた本数 (5 分割それぞれ) と AUC:

| 学習率 | 深さ 3 | 深さ 6 | 深さ 9 |
|---|---|---|---|
| 0.3 | 0.929 (44 から 132 本) | 0.928 (20 から 36 本) | 0.920 (6 から 19 本) |
| 0.1 | 0.930 (228 から 367 本) | 0.930 (73 から 107 本) | 0.929 (34 から 54 本) |
| 0.03 | 0.930 (665 から 970 本) | 0.930 (271 から 345 本) | 0.922 (36 から 190 本) |

- 学習率を小さくすると、選ばれる本数が増えるが、AUC はほとんど変わらない。学習率 x 本数がおおむね一定になる (深さ 3 で 0.3 x 約 110、0.1 x 約 290、0.03 x 約 870)。
- 深くすると、少ない本数で止まる。台東区では深さ 9 で少し悪くなった。データの少ない問題で深い木は過学習しやすい。23 区 (20 万行) では深さ 9 でも落ちなかった (0.892 から 0.894)。
- 早期打ち切りなしの曲線では、検証の AUC は山を作ってから下がり、学習の AUC は 1.0 に向かって上がり続ける。学習率が小さいほど山は後ろにずれてなだらかになり、行き過ぎても下がり方がゆっくり。山の高さは学習率 0.03 がわずかに高い (0.935 ほど) が、木を 10 倍使う。

## 3-A との違い

同じ XGBoost でも、無電柱化では 0.930、携帯の速度 (3-A) では R² 0.07 だった。ブースティングの強さは、特徴量に信号があって初めて出る。
