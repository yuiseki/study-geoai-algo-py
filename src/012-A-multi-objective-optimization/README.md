# 12-A 多目的最適化: 覆う人、拠点の数、浸水を、重み付き和で比べる

```sh
uv run python -u src/012-A-multi-objective-optimization/run.py
```

8-A の最大被覆 (台東区、WorldPop 100m 格子 1,422、候補地 566、歩いて 400m) に、目的を 2 つ足す。数字は 2026-09-29 に回したもの (`output/run.log`)。8GB の上限で囲み、最大 856MB、201 秒。

1. 400m 以内に入る人を多く
2. 開く拠点の数 (費用) を少なく
3. 浸水しやすい所を避ける: 候補地ごとの浸水深ランクを、開いた拠点について足したものを小さく

浸水深ランクは、国土数値情報 A31a の想定最大規模 (浸水深ランク `A31a_205`) で、荒川、隅田川、神田川のうち、その地点で最も深いもの。0 は想定の外、1 は 0.5m 未満、2 は 3m まで、3 は 5m まで、4 は 10m まで (国土数値情報のコード表による)。

## 候補地の多くは浸水する

| 浸水深ランク | 候補地 | それだけを全部開いたときに 400m 以内に入る人 |
|---:|---:|---:|
| 0 (想定の外) | 63 | 22.5% |
| 1 (0.5m 未満) | 21 | 14.5% |
| 2 (3m まで) | 312 | 71.1% |
| 3 (5m まで) | 170 | 71.0% |

(`output/flood-rank-taito.png`)

- 候補地の 89% が、想定最大規模の浸水区域の中にある。浸水しない候補地を 63 か所すべて開いても、400m 以内に入るのは 22.5% の人だけ。区の東側の大部分が、荒川の氾濫で 3m から 5m 浸水する想定になっているため。
- つまり「多くの人の近くに置く」と「浸水しない所に置く」は、強くぶつかる。

## 重み付き和

`覆う人 − w_site × 拠点の数 − w_flood × 浸水ランクの和` を最大にする (拠点の数は自由)。w_site は「拠点を 1 つ開くのに、何人増えれば割に合うか」、w_flood は「浸水ランク 1 つを避けるのに、何人までなら諦めるか」。w_site 5 通り x w_flood 7 通りの 35 回を解いた (`study_geoai.cover.solve_multi`、scipy の `milp` から HiGHS)。

- 35 回から 22 の異なる解が出て、22 のすべてが、互いの間ではほかに負けていない (パレート最適)。
- w_flood が 4,000 (w_site が 5,000 以上なら 2,000) を超えると、どの w_site でも浸水 0 の解に飛ぶ。浸水 0 の解は、拠点 1 から 13 か所で、覆う人は 4 から 21%。
- 浸水を少しだけ許して覆う人を増やす、という中間の解はほとんど出ない。例えば w_site 1,000 では、w_flood 2,000 で「28 か所、76%、浸水 34」、4,000 で「13 か所、21%、浸水 0」と、あいだが飛ぶ。浸水 0 から 34 のあいだの解は、この重みの組では 1 つも出なかった。

| 拠点 | 覆う人 | 浸水ランクの和 | 出てきた重み (w_site, w_flood) |
|---:|---:|---:|---|
| 1 | 3.8% | 0 | (8000, 1000) ほか |
| 4 | 11.9% | 0 | (5000, 2000) ほか |
| 4 | 18.4% | 11 | (8000, 500) |
| 9 | 38.3% | 26 | (8000, 0) |
| 13 | 21.1% | 0 | (1000, 4000) ほか |
| 13 | 48.7% | 21 | (5000, 1000) |
| 20 | 72.4% | 46 | (5000, 0) |
| 28 | 76.0% | 34 | (1000, 2000) |
| 31 | 87.3% | 49 | (1000, 1000) |
| 40 | 95.3% | 79 | (1000, 0) |

(22 すべては `output/run.log`、図は `output/weighted-sum-taito.png`)

- 図では、浸水 0 の解 (黄) が左下に、浸水を許す解が右上に分かれ、そのあいだが空いている。
- 同じ 13 か所でも、浸水 0 なら 21.1%、浸水 21 を許せば 48.7%。浸水を避ける代償の大きさが、数で見える。

## 気をつけること

- 「パレート最適」は、この 22 の解の中で互いに負けていない、という意味でしかない。重みの組が粗いので、あいだの解を見落としている。重み付き和は、そもそも出せない解がある (12-B)。
- w_flood が 0 で w_site が小さい 2 回 (1,000 と 2,000) は、解くのに 44 秒と 60 秒かかり、60 秒のほうは時間切れで打ち切った。その解は最適でないかもしれない。浸水を重く見る重みでは、どれも 0.1 秒で解けた (浸水しない 63 か所に候補が絞られるため)。
- 浸水ランクの和は、深さのランクを足しただけの目安で、実際の被害の大きさではない。

## まとめ

- 3 つの目的のうち、覆う人と浸水の回避が強くぶつかる。台東区の候補地の 89% が浸水区域にあるため。
- 重み付き和は、重みを振ると解が大きく飛び、中間の解がほとんど出ない。重みの小さな違いで答えががらりと変わるので、重みを決める人が「何人と浸水 1 ランクを交換するか」を意識する必要がある。
