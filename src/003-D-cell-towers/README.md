# 3-D 基地局を足す: 携帯の下り速度は予測できるようになるか

```sh
uv run python src/003-D-cell-towers/run.py
```

3-A と同じタイル、目的変数、測り方 (23 区 2,246 タイル、下りの平均速度の対数、測定回数で重み付けした R²、5 分割 (ランダム) の予測をまとめて測る、学習にも測定回数の重み) に、OpenCelliD の基地局 (2024-06-14 時点、`study_geoai.opencellid`) をタイルごとに足した。数字は 2026-09-29 に回したもの。

## 足した特徴量

| 特徴量 | 速度 (対数) との相関 |
|---|---:|
| タイルの中のセルの数 (対数) | +0.194 |
| うち LTE の数 (対数) | +0.194 |
| うち NR (5G) の数 (対数) | +0.058 |
| タイルの中の事業者 (net) の数 | +0.138 |
| タイルの中心から最寄りのセルまでの距離 (対数) | -0.124 |
| タイルの中のセルの推定カバー範囲の平均 (対数) | +0.014 |

23 区のセルは 86,795 件 (LTE 77,215、UMTS 8,687、NR 893)。

## 結果

| モデル | 基地局なし | 基地局あり |
|---|---:|---:|
| 線形 | 0.059 | 0.044 |
| scikit-learn HistGB | 0.095 | -0.009 |
| XGBoost | 0.068 | 0.010 |
| LightGBM | -0.009 | -0.007 |
| CatBoost | 0.081 | 0.120 |

基地局を足しても、ほとんど良くならない。CatBoost だけが 0.12 まで上がり、ほかは下がるか横ばい。特徴量を足すと下がるモデルがあるのは、信号の弱い問題で、足した列の雑音に合わせてしまうため。

OpenCelliD の位置は利用者の観測から推定したもので、実際の基地局の位置ではない。事業者 (net) も分けていないし、Ookla の速度も事業者を分けていない。速度を決めるはずの「どの事業者の、どの局に、どれだけの人がつないでいるか」は、この材料では見えない。

どこまでが説明できる上限なのかは、3-C で、同じタイルの別の四半期の速度との一致から測る。
