# 3-A 勾配ブースティング: 携帯の下り速度 (23 区)

```sh
uv run python src/003-A-gradient-boosting/run.py
```

数字は 2026-09-29 に回したもの (`output/run.log`)。メモリは 8GB の上限 (`systemd-run --scope -p MemoryMax=8G`) で囲み、最大 433MB だった。

## 問題

- 行: Ookla の携帯のタイル (ズーム 16、約 610m 四方)、2026 年第 2 四半期。23 区は 2,246 タイル、台東区は 62 タイル。
- 目的変数: 下りの平均速度 (kbps) の対数。23 区の中央値は 93Mbps。
- 特徴量 (`study_geoai.features.tiles`): WorldPop 2025 年の人口、Overture の建物の面積の割合と数、POI の数、みちよみの無電柱化の割合、見える電柱の平均、緑の割合の平均。
- タイルの値は、そのタイルの測定の平均。23 区で測定が 1 回だけのタイルが 16%、10 回以上は 34%。
- 点数は、測定回数で重み付けした R² を、5 分割 (ランダム) の予測をまとめて 1 回で測った。学習に測定回数の重みを付けるかどうかも比べた。

## 結果: ほとんど予測できない

23 区 (括弧の中は重みなしの R²):

| モデル | 学習に重みなし | 学習に重みあり |
|---|---:|---:|
| 線形 | 0.086 (0.066) | 0.059 (0.013) |
| ランダムフォレスト | 0.027 (0.039) | 0.055 (0.041) |
| scikit-learn HistGradientBoosting | 0.001 (-0.049) | 0.095 (0.001) |
| XGBoost | -0.032 (-0.023) | 0.068 (0.008) |
| LightGBM | 0.020 (-0.037) | -0.009 (0.009) |
| CatBoost | 0.065 (0.026) | 0.081 (0.031) |

台東区 (62 タイル) は、どのモデルも R² がマイナス (-0.17 から -0.55)。

- どのモデルも 0.1 に届かない。人口、建物、POI、街路の様子からは、携帯の下り速度はほとんど説明できない。
- ブースティングの 4 つの間の差 (-0.03 から 0.10) は、この程度の信号では意味のある差ではない。どれが強いかは、信号のある問題でないと比べられない。
- 学習に重みを付けると、重み付きの R² はおおむね上がり、重みなしの R² は下がる。測定の多いタイルに合わせる代わりに、少ないタイルを捨てている。
- LightGBM の gain の重要度は POI の数が 0.32 で最も大きいが、当てはまりが 0.1 未満なので、重要度も読むべきではない。

## なぜ予測できないのか (仮説)

- 速度を決めるものが特徴量に入っていない。基地局までの距離や混み具合、事業者、端末、測った時間帯など。
- 1 タイルの測定が少なく、平均そのものが雑音で揺れる。どこまでが説明できる上限かを、別の四半期と比べて測る (3-C)。

## 続きの実験

- 3-B: 信号のある問題 (無電柱化) で、XGBoost の早期打ち切りと学習率を見る。
- 3-C: 同じタイルの別の四半期の速度との一致から、説明できる上限 (雑音の天井) を測る。
- 3-D: OpenCelliD の基地局を特徴量に足す。
