# 10-A CP-SAT: 時刻表を回すのに最少で何台のバスが要るか

```sh
uv run python src/010-A-cp-sat/run.py
```

コミュニティバスの GTFS には、どのバスがどの便を走るか (`block_id`) が書かれていない。平日の便の始発と終着の停留所と時刻から、全便を回す最少の台数を、OR-Tools の CP-SAT で求める (`study_geoai.schedule`)。数字は 2026-09-29 に回したもの (`output/run.log`)。8GB の上限で囲み、最大 508MB、7 秒。

## モデル

- つながり (弧): 便 a の後に同じバスで便 b を走れるのは、a の終着から b の始発の停留所へ間に合うとき。終着での折り返し時間 (3 分) と、停留所が違うなら回送 (直線距離を時速 15km) を足しても、b の出発に間に合うこと。
- CP-SAT の変数は弧ごとの 0 か 1。どの便も「次の便は 1 つまで」「前の便は 1 つまで」。つないだ便の列が 1 台のバスになるので、台数 = 便の数 − 使った弧の数。使う弧の数を最大にする。
- 確かめ方が 2 つある。
  - 二部グラフの最大マッチング (scipy の `maximum_bipartite_matching`)。「便を最少の列で覆う」問題は、最大マッチングで厳密に解ける (最小路被覆)。CP-SAT の答えと一致するはず。
  - 同時に走っている便の数の最大値 (ピーク)。どんな割り振りでも、これより少ない台数では回せない (下限)。
- 2 段目: 台数を最少に固定したまま、バスが停留所で待つ時間の合計を最小にする。

## 結果

| 路線 | 便 | 運行時間 | ピーク (下限) | 折り返し 3 分 | 折り返し 0 分 |
|---|---:|---|---:|---:|---:|
| 荒川区 さくら (毎日と平日) | 28 | 06:35 から 20:04 | 2 | 2 台 | 2 台 |
| 台東区 めぐりん (平日) | 171 | 06:59 から 20:55 | 14 | 17 台 | 14 台 |

- どの場合も、CP-SAT (すべて OPTIMAL) と最大マッチングの台数が一致した。CP-SAT は 1 秒以内で解いた。
- 荒川区は 2 台で、ピークの下限と同じ。1 台目が 23 便、2 台目が朝の 5 便 (06:50 から 09:48) を走る。手で追える大きさで、便の列 (`output/blocks-arakawa.png`) を見ても無理は無い。
- めぐりんは、折り返しを 3 分とると 17 台、0 分なら 14 台 (ピークと同じ)。折り返し 0 分での待ち時間の合計は 0.8 時間 (2 段目で 0.1 時間)。めぐりんの時刻表は、循環路線の終着に着いたバスがそのまま次の便として出発するように組まれていると考えられる。そのため、折り返しに数分を要求すると、その分だけ台数が増える。
- 2 段目は、台数を変えずに待ち時間を減らした (めぐりん 3 分: 36.4 時間 → 36.1 時間、0 分: 0.8 時間 → 0.1 時間)。

## 気をつけること

- 弧は路線をまたいでよいとした。めぐりんの 12,122 本の弧のうち、同じ停留所でつながるのは 3,179 本だけで、残りは別の停留所への回送。実際の運行では、バスが路線ごとに決まっていたり、回送の道や車庫の位置の制約があったりするので、この台数は楽観的な下限に近い。
- 回送の時間は直線距離を時速 15km で割ったもので、道路網は使っていない。
- 実際の台数は確かめていない。

## まとめ

- 「最少の台数で全便を回す」は、便をつなぐ弧を選ぶ問題として CP-SAT で数秒以内に解け、最大マッチング (最小路被覆) の厳密解と一致した。
- 台数は、終着での折り返しの余裕に敏感だった。めぐりんでは 3 分の余裕で 3 台増える。
