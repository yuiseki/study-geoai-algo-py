# 004-D 時系列: 東京の月ごとの気温と雨を予測し、時間の順に分けて評価する

```sh
uv run python -u src/004-D-time-series/run.py
```

AgERA5 (FAO FERSPAS) の 23 区にかかる 9 格子の平均で、日最高気温 (C) と雨 (mm) の月ごとの系列を作る。1979-01 から 2025-12 の 564 か月。数字は 2026-09-29 に回したもの (`output/run.log`)。8GB の上限で囲み、最大 436MB、36 秒。

評価は TimeSeriesSplit で、最後の 10 年を 12 か月ずつ 10 回に分ける。各回は、それより前のすべてで学習し、次の 12 か月を予測する。1 か月先と 12 か月先の 2 通り。

- 平年値 (climatology): 学習期間の同じ月の平均
- 季節ナイーブ: 12 か月前の値
- ETS: Holt-Winters (加法の傾向と季節、傾向は減衰。statsmodels の ETSModel)
- SARIMA (1,0,1)(0,1,1,12) (statsmodels の SARIMAX)
- ラグ特徴 + GBDT: 月、時刻、h か月前から h+11 か月前の値 (h は何か月先か)。予測の起点より後の値は使わない。

1 か月先では、ETS と SARIMA は学習期間で決めた係数のまま、起点までの観測を入れて次の月を出す。12 か月先では、起点から 12 か月をまとめて予測する。

## 気温

1 か月先の平均絶対誤差 (C。括弧は平年値との差と、平均の誤差。+ は予測が高すぎる):

- 平年値 1.46 (基準、-1.30)
- 季節ナイーブ 1.09 (-25%、-0.12)
- ETS 0.96 (-34%、-0.17)
- SARIMA 1.00 (-31%、-0.45)
- GBDT 1.04 (-29%、-0.26)

12 か月先でも順位はほぼ同じ (ETS 0.98、SARIMA 1.13、GBDT 1.10)。

- 平年値がいちばん悪い。1979 年からの平均は、温暖化した最近の 10 年より平均で 1.30C 低い。「過去の平均」は、傾向のある系列では偏った予測になる。
- 季節ナイーブは 1 年前の値なので、偏りは -0.12C と小さい。傾向を持つ ETS が最も良い。

## 雨

1 か月先の平均絶対誤差 (mm): 平年値 48.3、季節ナイーブ 61.6 (+28%)、ETS 49.0 (+2%)、SARIMA 48.8 (+1%)、GBDT 55.4 (+15%)。12 か月先の SARIMA が 48.25 で、平年値と並ぶ (-0.1%)。

- 月の雨は、どのモデルでも平年値を超えられない。過去の値に次の月の雨の手がかりが無い。003-C で携帯の速度が雑音ばかりだったのと同じ形。
- GBDT はラグから雑音を覚えて、平年値より 15% 悪くなる。

## 混ぜて分けると

同じ 1 か月先の GBDT を、年を混ぜた K-fold (10 分割) で採点すると、気温 0.94、雨 51.8。TimeSeriesSplit では 1.04 と 55.4。

- 混ぜた K-fold は 10% (気温) と 6% (雨) 甘い。ただしその一部は、試す月が全期間に広がることによるものと考えられる。最後の 10 年だけで比べると 1.01 と 53.8 で、差は 3% ほどに縮む。
- ラグ特徴が過去の値だけなので、この系列では、未来の行が学習に混ざることによる漏れは小さかった。004-B の撮影年の漏れと同じく、漏れの大きさはデータ次第。

## まとめ

- 傾向のある系列では、平年値は「平均からずれた予測」になる。傾向を扱う ETS や季節ナイーブのほうが良い。
- 雨のように手がかりの無い系列では、どの手法も平年値を超えず、柔軟なモデルほど雑音を覚えて悪くなる。
- 時系列は時間の順に分けて評価する。混ぜて分けると甘く出るが、その差の大きさは、何を特徴量にしたかと、どの期間で比べたかで変わる。
