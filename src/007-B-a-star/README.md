# 7-B A*: Dijkstra より探索をどれだけ減らせるか

```sh
uv run python src/007-B-a-star/run.py
```

7-A と同じ台東区の歩行者の道路網 (97,702 ノード) で、始点と終点の決まった最短経路を、Dijkstra と A* で比べる。数字は 2026-09-29 に回したもの (`output/run.log`)。8GB の上限で囲み、最大 455MB、30 秒。

A* は、「ここまでの距離 + 終点までの直線距離」の小さいノードから確定していく。直線距離は、道に沿った距離を決して超えない (辺はどれも頂点の間の直線なので)。そのため、A* は Dijkstra と同じ最短距離を返し、終点から遠ざかる方向を探さずに済む。直線距離を水増しして (inflation 倍) 使うと、探索はさらに減るが、最短でない経路を返すことがある。その長さは最短の inflation 倍を超えない。

## 1. 町丁目の中心どうしの 300 組

直線距離は中央値 1,611m、最大 3,652m。Dijkstra は終点を確定した時点で止める。

| 探索 | 確定したノード (中央値) | Dijkstra との比 | 時間 (中央値) | Dijkstra との比 | 最短との比 (中央値、最大) |
|---|---:|---:|---:|---:|---|
| Dijkstra | 20,572 | 1.00 | 45.6ms | 1.00 | 1.000、1.000 |
| A* | 2,017 | 0.12 | 9.7ms | 0.26 | 1.000、1.000 |
| A* 水増し 1.2 倍 | 648 | 0.05 | 3.4ms | 0.12 | 1.012、1.107 |
| A* 水増し 1.5 倍 | 162 | 0.01 | 1.0ms | 0.03 | 1.038、1.312 |
| A* 水増し 2 倍 | 121 | 0.01 | 0.8ms | 0.02 | 1.052、1.311 |
| A* 水増し 3 倍 | 118 | 0.01 | 0.8ms | 0.02 | 1.072、1.365 |

- A* は 300 組すべてで Dijkstra と同じ距離を返し、確定したノードは 1/10 になった。
- 時間は 1/4 にとどまる。A* は 1 つのノードごとに直線距離を計算するので、ノードあたりの手間が Dijkstra より大きい。
- 水増しすると探索は急に減る。1.5 倍でノードは Dijkstra の 1/100 になるが、経路は中央値で 4%、最悪で 31% 長くなった。1.5 倍より大きくしても、探索はほとんど減らない (確定するのが経路の上のノードだけに近づくため)。長さの悪化だけが進む。

## 2. 距離に対する探索の増え方

最短距離 500m 以上の組で、確定したノードの数を距離の何乗で増えるかに当てはめた (`output/settled-by-distance.png`)。

| 探索 | 何乗で増えるか |
|---|---:|
| Dijkstra | 1.94 |
| A* | 2.04 |
| A* 水増し 2 倍 | 1.05 |

- Dijkstra は、始点のまわりの円を広げていくので、面積と同じく距離の 2 乗で増える。
- A* も 2 乗で増えた。減ったのは係数 (1/10) で、増え方は変わらない。A* が探すのは始点と終点を焦点とする楕円のような範囲で、道が直線より 3 割長い (7-A の迂回率 1.3) と、その楕円の幅も距離に比例して広がるため、面積はやはり 2 乗で増える。
- 水増し 2 倍では、ほぼ経路に沿ったノードしか確定しないので、距離に比例する (1 乗)。

最も長い組 (4,296m) で確定したノード (`output/settled-map.png`): Dijkstra 62,200、A* 14,272、水増し 2 倍 556。地図の上でも、Dijkstra は始点を中心に広がり、A* は始点と終点の間の楕円、水増し 2 倍は経路の近くだけを探している。

## 3. 7-A の遠回りを描いて確かめる

7-A で迂回率の大きかった 3 つの経路を描いた (`output/detour-*.png`)。どれも、直線が「道の無い帯」を横切っていて、経路はその帯を渡れる所まで回り込んでいた。

| 経路 | 歩く | 直線 (ノードの間) | 見えたもの |
|---|---:|---:|---|
| 池之端二丁目 → 東京大学医学部附属病院 | 832m | 400m | 直線上の大学の区画の中に OSM の道が無く、区画の東側を大回りして入る。7-A では「不忍池を回る」と推測したが、違った |
| 根岸一丁目 → 上野中学校 | 789m | 331m | 道の無い斜めの帯 (鶯谷の線路と考えられる) を、南の渡れる所まで回って越える |
| 駒形二丁目 → 墨田病院 | 702m | 373m | 隅田川を、南の橋まで回って渡る |

- 池之端の遠回りは、実際の街の形だけでなく、「大学の敷地の中の道が OSM に描かれていない」ことにもよる。病院の入口や敷地の中の通路が描かれていれば、もっと短くなるかもしれない。最短経路の結果は、道路網のデータの描き込み具合に左右される。

## まとめ

- 直線距離という「決して長すぎない目安」を足すだけで、A* は Dijkstra と同じ答えを 1/10 の探索で返す。ただし探索の増え方 (距離の 2 乗) は変わらない。
- 目安を水増しすると探索はほぼ経路の上だけになるが、最短との差は保証の範囲 (水増しの倍率) の中で大きくなる。1.2 倍あたりが、速さと正確さの釣り合いのよい所だった (探索 1/20、最悪 11% 長い)。
