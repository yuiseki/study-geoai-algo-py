# 国土地理院 電子国土基本図（地名情報）「住居表示住所」

2026-10-03 に読んで確かめた内容。ページは取得して読んだ。大きさと Last-Modified は 674 本すべての ZIP への HEAD、ZIP の中身の一覧は各 ZIP の末尾 8KB を Range で取って中央ディレクトリを読んだ値。CSV の中身は `11104.zip` (さいたま市見沼区、2,055 bytes) と `13101.zip` (千代田区、406,524 bytes) の 2 本だけを取得して見た。

- 入口: <https://www.gsi.go.jp/kihonjohochousa/jukyo_jusho.html>
- ダウンロード: <https://saigai.gsi.go.jp/jusho/download/index.html> (都道府県の一覧から市区町村ごとの ZIP へ進む)
- 閲覧サービス: <https://saigai.gsi.go.jp/jusho/view/index.html>
- 作成: 国土交通省 国土地理院 基本図情報部 (ファイル仕様書とメタデータの作成者)。基本測量成果。
- ファイル仕様書: <https://www.gsi.go.jp/common/000255933.pdf> (第 1.5 版、2025-07-31)
- 更新の一覧: <https://www.gsi.go.jp/common/000261022.pdf> (「更新項目」、最終更新日 2026 年 3 月 26 日)

`www.gsi.go.jp` は TLS の古い再ネゴシエーションを要求し、OpenSSL 3 の curl では `unsafe legacy renegotiation disabled` で繋がらない。Python で `ssl.OP_LEGACY_SERVER_CONNECT` (0x4) を立てると読めた。`saigai.gsi.go.jp` はふつうの curl で読める。

## 何のデータか

入口のページの説明:

> 電子国土基本図（地名情報）「住居表示住所」とは、「住居表示に関する法律」による住居表示が行われている地区の住居番号（○○市○○○丁目○番○号という住所のうち、「○号」に該当する番号）を決める際に用いる「基礎番号」を国土地理院がデータ化した基本測量成果です。

> 電子国土基本図（地名情報）「住居表示住所」は、フロンテージの中央付近に点を取得し、その点に市区町村コード、町名、街区符号、基礎番号、点の取得精度を与えたものです。

- 1 件は 1 つの基礎番号の点。「○丁目○番○号」の「号」の手前まで (町名、街区符号、基礎番号) と、その点の緯度経度を持つ。
- 住所の列がある。緯度経度もある。建物の点ではなく、街区の縁に沿った区間 (フロンテージ) の中央付近の点。
- 対象は住居表示を実施している地区だけ。地番で住所を表す地域は入らない。
- ページの注意事項: 「個別の建築物を識別するものではありません」「基礎番号に対応する住居番号を持つ建築物が必ず存在するとは限りません。また、すべての住居番号に対して対応する基礎番号があるとは限りません」「データ作成当時の住居表示台帳に基づき作成しているため、現在の状況と合わない場合があります」。
- 作り方 (ページの Q&A): 市区町村から提供を受けた住居表示台帳を、基盤地図情報や電子国土基本図 (オルソ画像) 等の測量成果に位置合わせして作成。

## 配布ファイル

- 市区町村 (政令指定都市は区) ごとに 1 本の ZIP。URL は `https://saigai.gsi.go.jp/jusho/download/data/<市区町村コード5桁>.zip`。
- 都道府県ごとのページ `https://saigai.gsi.go.jp/jusho/download/pref/<01〜47>.html` に並んだ ZIP は全部で 674 本。47 都道府県すべてに 1 本以上ある。多いのは大阪府 65、北海道 53、埼玉県 45、神奈川県 43、福岡県 38、東京都 36。少ないのは石川県、京都府、鳥取県、徳島県の 2。
- 674 本すべてに HEAD を送り、すべて 200。合計 1,254,255,588 bytes (約 1.25GB)。最小は `11104.zip` (さいたま市見沼区) の 2,055 bytes、最大は `34202.zip` (呉市) の 13,264,606 bytes。
- どの ZIP も中身は 6 ファイル: CSV 1 本と、`shp/` の下の Shapefile 一式 (`.shp` `.shx` `.dbf` `.prj` `.cpg`)。ファイル名は `<コード>/j<コード>k_<日付>.csv`。
- 中の CSV の合計は 2,418,312,672 bytes (約 2.4GB、展開後)。最小は見沼区の 1,138 bytes (11 行)、最大は呉市の 25,768,247 bytes。
- メタデータ (JMP 2.0): <https://saigai.gsi.go.jp/jusho/download/dkgni-jusho-2025.xml>。日付は 2025-07-31。

## 中身

ファイル仕様書の「7. データ製品配布」:

> 4.2 に定める情報項目をその順序に格納した CSV 形式（ヘッダ行及びダブルクォートなし。UTF-8 符号化。改行コードは CR+LF）による。

見出し行は無い。列は仕様書の 4.1 の順で 9 列。

| 列 | 名前 | 型 | 千代田区での例 |
|---:|---|---|---|
| 1 | 市区町村コード | 文字列 (5 桁、検査数字なし) | `13101` |
| 2 | 町又は字の名称 | 文字列 | `飯田橋一丁目` |
| 3 | 街区符号 | 文字列 | `3` |
| 4 | 基礎番号 | 文字列 | `1` |
| 5 | 住所コード（可読） | 文字列 (URI 形式) | `http://gi.gsi.go.jp/jusho/13101/IDB-1/3/1` |
| 6 | 住所コード（数値） | 空 | (空) |
| 7 | 経度 | 実数 (度、小数 9 桁) | `139.749948508` |
| 8 | 緯度 | 実数 (度、小数 9 桁) | `35.697951708` |
| 9 | 地図情報レベル | 整数 (2500 か 25000) | `2500` |

- 経度が緯度より先に来る。
- 測地系は JGD2024 の緯度経度 (仕様書 5.1、`.prj` も `GEOGCS["JGD2024", ...]`)。
- `住所コード（数値）` は仕様書に「未定により現状は空である」。2 本とも全行が空だった。
- `町又は字の名称` の丁目は「十」を使い「〇」を使わない漢数字 (例 `二十丁目`)。
- 千代田区では、取得した 2 本とも列数は全行 9、改行は CR+LF だった。`地図情報レベル` は 2500 が 6,546 行、25000 が 780 行。仕様書の 6 章に「原則として地図情報レベル 2500 と同等程度の位置正確度とする。使用する測量成果によっては，地図情報レベル 25000 と同等程度の位置正確度となる」とある。
- 市区町村コードは政令指定都市では区のコード。行政区の再編 (浜松市、2024-01-01) では再編後のコードで出し直されている。

住所の文字列を組むには `町又は字の名称` + `街区符号` + `番` + `基礎番号` + `号` を自分で連結する。都道府県名と市区町村名の列は無いので、市区町村コードから引く。

## 取り出し方

区分は split。市区町村 (政令市は区) ごとの 674 本から必要なものだけ取れる。

- `curl -r 0-1023` は 206 を返した (`13101.zip`)。ZIP の末尾を Range で取れば、全体を落とさずに中のファイル名と展開後の大きさが分かる (この README の数字はそうして取った)。
- ただし中身は ZIP に圧縮された CSV と Shapefile なので、行の部分集合は選べない。各 ZIP の中は whole (最小 2,055 bytes、最大 13,264,606 bytes)。
- 目録は都道府県ごとの HTML ページ。機械可読の一覧は無い。`data/` のディレクトリ一覧は 403。
- e-Gov データポータル (CKAN) にも同じ ZIP への登録がある。`package_search?q=title:住居表示住所` で 50 データセット (概要 1、全国 1、ファイル仕様書 1、都道府県ごと 47)、ZIP の URL は重複を除いて 673 種類で、配布元が `saigai.gsi.go.jp` を指す。配布元の 674 本のうち `47326.zip` (北谷町) だけが e-Gov に無かった。e-Gov 側のメタデータの更新日は大半が 2024-06 で、`frequency_of_update` は「不定期」。目録として使うなら、配布元の都道府県ページのほうが新しい。

### 測量法

このデータは基本測量成果で、配布元のページのダウンロードの節に次の注記がある:

> このサイトは、測量法第27条第2項に基づく測量成果の提供を目的としているものです。
> ※成果の利用に際しては、測量法に基づく基本測量の測量成果の複製・使用承認申請が必要となる場合があります。

「国土地理院の測量成果の利用手続」(<https://www.gsi.go.jp/LAW/2930-index.html>) の「地図の利用手続パンフレット」(<https://www.gsi.go.jp/common/000223838.pdf>、2026-10-03 に読んだ) の 2 ページ目の「国土地理院の地図の利用手続フロー」は、手続の対象となる基本測量成果の一つとして「電子国土基本図（地名情報）「住居表示住所」」を名指ししている。フローの問いは順に次のとおり。

- Q2 地図としての利用を想定しているか。
- Q3 成果品を不特定多数の者に提供するか。提供しない例として「私的利用」「社内、サークル、同好会、学校その他教育機関など組織内での利用」「論文、試験問題に利用」が挙がり、その場合は申請不要で出典明示のみ。
- Q4-1 測量成果としての正確さを要するか。
- Q4-2 成果品に「位置座標」はあるか。Q&A (<https://www.gsi.go.jp/LAW/2930-qa.html>) の Q1-13 では、デジタルデータの座標は位置座標に当たる。一方で「ベクトル地図データから座標を削り、ある地域の注記のみ取り出して作成したテキストファイルは、「位置座標のない成果物」」。
- Q5 複製 (測量法第 29 条) か使用 (第 30 条) か。

Q&A の Q2-3 では、インターネットで誰でも入手できる状態に置くことを不特定多数への提供としている。Hugging Face に緯度経度ごと置く場合は、Q3 で「提供する」、Q4-2 で「位置座標あり」になる。Q4-1 の「正確さを要するか」をどう答えるかで申請不要か申請 (おそらく第 29 条の複製) かが分かれ、その判断はこのフローの文面だけでは決められない (未確認)。

- 同じ Q&A の Q5 の節には「営利・非営利に関わらず基盤地図情報はそのままの複製であっても無償で承認されます」とある。住居表示住所が同じ扱いかは書かれていない (未確認)。
- 座標を落として住所の文字列だけにしたものは、Q1-13 の「位置座標のない成果物」に当たると読める。その場合のフローの行き先は未確認。
- 申請が要るかを確かめる手段として、国土地理院は「地図の利用手続ナビ」(<https://service.gsi.go.jp/onestop/navi/index/>) と問い合わせフォームを案内している。どちらも試していない。
