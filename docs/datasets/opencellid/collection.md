# OpenCelliD の取得記録 (2026-10-06)

README.md で未確認としていたところを、API アクセストークンを使って確かめた。
収集用のリポジトリは `/sata_hdd_24tb/hf_data/opencellid/` にある。

## ダウンロードの URL の形

ドキュメント (docs.opencellid.org) には URL の形が書かれていない。
ダウンロードページ <https://opencellid.org/downloads.php> にトークンを POST すると、リンクの一覧が返る。
リンクは次の形である。

```
https://opencellid.org/ocid/downloads?token=<トークン>&type=<full|mcc|diff>&file=<ファイル名>
```

- `type=full` は全世界の `cell_towers.csv.gz` で、ページには大きさが出ず「Updated: 2026-10-06」とだけある。
- `type=mcc` は MCC ごとのファイル (`440.csv.gz` など) で、179 個あった。表示された大きさの合計は 110,543 KB である。
- `type=diff` は日ごとの差分で、名前は `OCID-diff-cell-export-2026-10-06-T000000.csv.gz` の形だった。ドキュメントの `cell_towers_diff-*.csv.gz` とは違う。直近 7 日分 (計 13,523 KB) が並んでいた。
- 「No recent data」とされた MCC が 14 個あった (374, 539, 540, 541, 546, 548, 549, 551, 607, 618, 619, 638, 657, 738)。

## 上限

ドキュメントには「You can download each file twice per day」とあり、API は利用者ごとに 1 日 1,000 リクエストである。
HEAD が回数に数えられるかは書かれていないので、HEAD は送っていない。
全世界のファイルは 1 回だけ取得した。上限のエラーには当たっていない。
ページへの POST はダウンロードではないので、回数に入らないと見ている。

## 気づいたこと

- `unit` は空にならない。ドキュメントは GSM と CDMA では空としているが、実際は 0 か -1 が入っている。LTE も 2,618,144 件が -1 である。
- `range` がちょうど 1000 の行が 3,109,353 件 (57%) あり、既定値らしい。`samples` が 1 の行は 916,581 件である。
- 全世界のファイルには、国別ファイルの無い MCC が 20 個ある。374 (トリニダード・トバゴ) は「No recent data」とされているのに 13 件入っていた。
- 18 か月より古いセルは後のファイルから消えるので、取得したファイルは日付ごとのスナップショットとして残し、上書きしない。
