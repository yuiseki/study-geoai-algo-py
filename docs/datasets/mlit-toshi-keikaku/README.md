# 都市計画決定GISデータ (国土交通省 都市局)

2026-10-06 に読んで確かめた内容。ページは curl と Python の urllib で取得して読み、全 146 ファイル (約 2.03GB) を取得して中身を数えた。取得と変換の手順は `/sata_hdd_24tb/hf_data/mlit-toshi-keikaku-jp/` にある。

- 入口 (使用許諾条件と更新履歴): <https://www.mlit.go.jp/toshi/tosiko/toshi_tosiko_tk_000087.html>
- ダウンロード表 (都道府県 × 形式): <https://www.mlit.go.jp/toshi/tosiko/toshi_tosiko_tk_000182.html>
- 案内ページ: <https://www.mlit.go.jp/toshi/tosiko/toshi_tosiko_tk_000190.html> (運用開始は 2024 年 7 月 5 日の報道発表)
- 作成: 国土交通省 都市局 都市計画課 都市計画調査室
- 中身は、全国の市区町村の都市計画決定 (用途地域、都市計画区域、区域区分、都市計画道路、公園、地区計画、立地適正化計画など 26 レイヤ) を GIS データにしたもの。
- [toshik](../source-coop-smartmaps/toshik.md) (UN Smart Maps の PMTiles) の元データにあたる。ただし toshik は以前の版から作られていて、属性の体系が違う (下記)。

## 版と更新のしかた

- 入口ページの「データ作成年度」は令和7年度 (fy2025)。更新履歴は「令和8年5月21日」「令和8年7月1日（シェープファイル形式・GeoJSONファイル形式　一部修正）」「令和8年7月2日（同）」「令和8年7月7日（CityGMLファイル形式　一部修正）」。
- ページに載る版は 1 つだけ。過去の版へのリンクは無い。
- 修正はファイルの差し替えで行われる。ダウンロード表のセルに「（R8.7.1修正）」のような注記が付き、シェープファイルと CityGML の ZIP は URL がそのまま (中身と Last-Modified が変わる)、GeoJSON は新しい URL になっていた。修正の注記が付いたのは 11 都府県 (岩手、東京、神奈川、長野、滋賀、京都、大阪、奈良、島根、熊本、宮崎)。
- 東京都のシェープファイル ZIP は Last-Modified が 2026-07-17 で、更新履歴にない差し替えがその後もある。
- したがって版ごとに残すのではなく、同じ版の中では配布元に追随する作りにした (`01_download.py --refresh` が Content-Length と Last-Modified を比べて取り直す)。新しいデータ作成年度が出たら別のディレクトリになる。
- toshik の PMTiles (2024-05-08) は `kubunID`、`YoutoID`、`告示番号`、`決定日` のような属性名で、令和7年度版の `YoutoCode`、`FNNumber`、`FNDate` とは違う。以前の版は今は取れないので、toshik の中身を令和7年度版と比べて差を論じることはできない。

## 属性

データ定義書が全レイヤの属性名を決めていて、実データもそのとおりだった (同じレイヤ内で属性名の揺れは無い)。

- 共通: `Pref`、`Citycode` (5 桁、全行がファイル名の市区町村コードと一致)、`Cityname`、`INDate` (当初決定日)、`FNDate` (最終告示日)、`ValidType`、`Custodian` (定める者)、`INNumber`、`FNNumber` (告示番号)。
- 種類: `YoutoName`/`YoutoCode` (用途地域 1 から 13)、`AreaType`/`AreaCode` (区域区分 22・23、防火 24・25、誘導区域 31・32)、`DistType`/`DistCode`、`DouroType`/`DouroCode` (3011 道路、3023 広場)、`ParkType`/`ParkCode` (3021 公園、3022 緑地、3024 墓園)、`TokeiCode` (21)。コードは都市計画データ標準製品仕様書のコードリストに準拠とある。
- 用途地域だけ `FAR` (容積率 %) と `BCR` (建蔽率 %) がある。DBF では文字列 (`"200.0"`) で、FAR が空の行が 8,561 ある。
- 型の揺れ: コード類は DBF の数値型 N(18,0)。一方、本来文字列の `ValidType`、`INDate`、`INNumber`、`Custodian` などが、一部の市区町村では数値型 N(24,15) で、値はすべて `*` 埋め (DBF の空値) だった。中身のある値は無かった。toshik で見えた `kubunID` の数値と文字列の揺れのような問題は、令和7年度版では型の揺れとしては残っていない。
- 日付は自由書式のまま: `昭和48年12月25日`、`S43.3.13`、`1937-12-19`、`2024/03/29`、`H25.04.26`、全角数字、告示番号付き (`平成26年9月30日 県告示第624号`) など。ほとんどが空で、用途地域の `INDate` は 102,159 行中 101,092 行が空。
- `Custodian` は市名、`国`、`3` のような値が混在する。
- 用途地域に `YoutoCode` 0 (`調整`、茅ヶ崎市の 6 行) があり、定義書のコード表に無い。立地適正化計画の `AreaCode` 0 は定義書どおり計画区域そのもの。
- 改行 (CR、LF) を含む文字列値が 539 ある。先頭が空白の値は無い。
- ジオメトリが空 (null shape) のレコードがある: 都市計画道路 5,802 (3 市区町村)、防火 109、特別用途地区 65、高度利用地区 7、高度地区 1。

## 座標参照系

- データ定義書は「座標参照系：JGD2011 / (B,L)」「文字集合：UTF-8」。シェープファイルの `.prj` は全部 `GCS_JGD_2011` で、GDAL は EPSG:6668 と読む。
- GeoJSON は EPSG:6668、CityGML は EPSG:6697 (JGD2011 の地理座標と標高)。

## 変換して確かめたこと

`/sata_hdd_24tb/hf_data/mlit-toshi-keikaku-jp/` でシェープファイルを DuckDB の spatial (ST_Read) でレイヤごとの GeoParquet 26 本 (計 598MB) にし、自前の DBF、SHP、WKB の読み取りで次を確かめた。

- 全 4,967,475 個の属性値が DBF と一致 (UTF-8 として厳密に復号)。
- 全ジオメトリの座標のバイト列が `.shp` のレコードと一致 (パートの集合として比較)。
- GeoJSON の地物数がシェープファイルと全ファイルで一致。

## 12 ステップでの使いみち (案)

- 2 決定木 / Random Forest: 用途地域 (`YoutoCode`) を FAR、BCR と周辺の地価から当てる多クラス分類。
- 1 回帰 / 3 GBDT / 11 SHAP: 地価公示の説明変数として、地点の用途地域、容積率、区域区分、立地適正化計画の誘導区域を空間結合で足す。
- 4 CV とデータリーク: 同じ市区町村の区域は同じ告示で決まるので、`Citycode` 単位の group CV の題材になる。
- 9 facility location: 公園と居住誘導区域を、施設配置の候補地や制約に使う。
- 前処理: 和暦と西暦が混ざる日付の正規化そのものが練習題材になる。
