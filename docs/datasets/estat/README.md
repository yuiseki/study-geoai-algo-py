# e-Stat (政府統計の総合窓口)

2026-09-30 に読んで確かめた内容。数と大きさはこの日に実際に要求を投げて数えたもの。

- 日本の政府統計の窓口。運用管理は独立行政法人統計センター。
- 入口: `https://www.e-stat.go.jp/`
- 規約: `https://www.e-stat.go.jp/terms-of-use`
- この項目は e-Stat という出典そのものを扱う。国勢調査の小地域境界だけは既に
  [estat-boundary/README.md](../estat-boundary/README.md) に立ててあり、ここはその上位にあたる。
- 統計 LOD (SPARQL) は [lod.md](lod.md)。

e-Stat には性質の違う三つの経路がある。どれを使うかで、要る手続きも、取り出し方の区分も変わる。

| 経路 | 入口 | 認証 | 取り出し方 |
|---|---|---|---|
| 統計 GIS (境界データ / 統計データ) | `/gis/statmap-search` | 不要 | catalog + split |
| 統計データ API 3.0 | `api.e-stat.go.jp/rest/3.0/` | アプリケーション ID が要る | catalog |
| 統計 LOD | `data.e-stat.go.jp/lod/sparql/` | 不要 | catalog (SPARQL) |

## 統計 GIS には機械可読の目録がある

[estat-boundary/README.md](../estat-boundary/README.md) は「目録は無い。`code` を 01 から 47 まで自分で回す」
と書いていたが、これは誤りだった。人が見る画面 `/gis/statmap-search` は確かに JavaScript で描いていて
HTML には何も出てこないが、その画面が叩いている先が JSON を返す。

```
https://www.e-stat.go.jp/gis/statmap-search/search_detail
```

`/modules/custom/gis_download/js/gis_download-main.js` の中で `$.ajax({url:"/gis/statmap-search/search_detail"})`
として呼ばれている。この JS の中に出てくる ajax の宛先はこれ一つだけで、画面の全階層がこの
エンドポイントの引数違いで賄われている。認証は要らない。

応答は JSON だが、値は HTML の断片。`detail` に一覧の行が、`paginate` に総ページ数が、
`side_mega` に総件数が入る。行の中の `href` が次の階層への引数を持っているので、
それを辿れば全数を列挙できる。

| 引数 | 意味 |
|---|---|
| `type` | 1 が統計データ、2 が境界データ |
| `aggregateUnitForBoundary` | A 小地域、S 3次メッシュ (1km)、H 4次 (500m)、Q 5次 (250m)、E 6次 (125m) |
| `toukeiCode` | 政府統計コード。境界データは 5 つ |
| `toukeiYear` | 調査年 |
| `serveyId` | 配布物の ID。`dlserveyId` として配布 URL に渡すもの |
| `datum` | 2000 が JGD2000、2011 が JGD2011 |
| `coordsys` | 1 が緯度経度、2 が平面直角座標系 |
| `format` | shape、kml、gml |
| `prefCode` | 都道府県 |
| `download_disp_flg` | 1 にしないと末端の一覧が空で返る |

最後の `download_disp_flg=1` が要る。これを付けないと `detail` が空文字列のまま
`paginate` だけが「1/3ページ」と返り、行が無いのに件数はあるという応答になる。
一覧が取れないのはエラーではなく、引数不足の静かな失敗として出る。

## 境界データは 54 種類ある

`type=2` を全数辿ると 54 件だった。取得したものは [boundary-catalog.tsv](boundary-catalog.tsv)。

| 政府統計 | 件数 | 年 |
|---|---:|---|
| 国勢調査 | 14 | 2000, 2005, 2010, 2015, 2020 |
| 事業所・企業統計調査 | 1 | 2001 |
| 経済センサス－基礎調査 | 3 | 2009, 2014 |
| 経済センサス－活動調査 | 6 | 2012, 2016, 2021 |
| 農林業センサス | 30 | 2005, 2010, 2015, 2020 |

国勢調査 2020 年だけでも三種類ある。小地域 (町丁・字等)、小地域 (基本単位区)、人口集中地区で、
それぞれに JGD2000 版と JGD2011 版がある。既存の項目が扱っているのは
このうち `A002005212020` の JGD2000 の一つだけ。

東京都 (`code=13`) の Shapefile で 54 件すべての大きさを測ると、合計 204,112,811 バイト。
全国は東京都の約 56.8 倍 (国勢調査 2020 年の小地域で 322,733,398 / 5,682,172) にあたるので、
境界データ全体でおよそ 10.8GiB と見積もれる。

この 54 件には JGD2000 版と JGD2011 版が別々に数えられている。測定は `datum` を
付けずに投げたので、JGD2011 の行も実際には JGD2000 のファイルを測っている。
両者の差は東京都の国勢調査 2020 年で 5,682,172 と 5,679,981、0.04% なので
総量の見積もりには効かないが、個々の行の値は JGD2000 のものだと承知して読む。

最大は経済センサス－活動調査 2021 年の 8,347,507 バイト、最小は国勢調査 2020 年の
小地域 (基本単位区) で 8,111 バイト。後者は明らかに小さく、中身を確かめずに使うべきではない。

農林業センサス 2020 年の五つ (農林業経営体、農業経営体、農業経営体 (個人経営体)、
調査客体候補名簿、農山村地域調査) は東京都でどれも 4,255,925 バイトで一致した。
md5 は五つとも違うので別物ではあるが、大きさだけでは区別がつかない。

## datum と市区町村単位

既存の項目に二つ足りないものがある。どちらも実際に投げて確かめた。

`datum` が配布 URL の引数として効く。

| URL | 応答 |
|---|---|
| `...&code=13&coordSys=1&format=shape&downloadType=5` | 5,682,172 バイト、`A002005212020DDSWC13.zip` |
| 同上 + `&datum=2000` | 同じ。md5 も `eef747abb853...` で一致 |
| 同上 + `&datum=2011` | 5,679,981 バイト、`A002005212020DDSWC13-JGD2011.zip`、md5 は別 |

`datum` を書かないと JGD2000 が返る。既存の項目が記録している URL はすべてこの既定に
乗っているので、取ったものが JGD2000 だという事実が URL からは読めない状態になっている。

分割は都道府県より細かい。`code` に 5 桁の市区町村コードを渡せる。

| `code` | 応答 |
|---|---|
| `13` (東京都) | 5,682,172 バイト |
| `13106` (台東区) | 45,783 バイト |

既存の項目の「分割の単位は 1 都道府県 1 zip で、それより細かくは取れない」は誤り。
台東区だけなら 124 分の 1 で済む。

形式も一つ多い。`format=gml` が 200 を返す (`A002005212020DDMWC13.zip`)。
既存の項目は shape と kml しか試しておらず、geojson の 404 だけを記録している。

## 公開日は目録が持っている

末端の一覧には「公開（更新）日」の列がある。国勢調査 2020 年の小地域境界は
47 都道府県すべてが 2022-06-24。zip の中のメンバーの時刻 (2022-06-23) より 1 日新しい。
既存の項目は「日付は zip の中のメンバーの時刻でしか分からない」と書いているが、
目録を読めば配布側が申告している日付が取れる。

## 統計データ側は更新されている

`type=1` は同じ 5 つの政府統計を持つ。国勢調査 2020 年のメッシュ統計は
公開 (更新) 日が 2025-10-09 で、境界データ (2022 年) よりずっと新しい。

1km、500m、250m、125m の四段階があり、それぞれに人口及び世帯、人口移動・就業状態等、
5 歳階級別人口、労働力状態・産業分類・職業分類別人口、住宅の所有及び建て方、
5 年前の常住地等の六つが、JGD2000 版と JGD2011 版で置かれている。
第 1 次地域区画 (80km メッシュ) 単位と都道府県単位の二通りで分割されている。

## 統計データ API 3.0

```
https://api.e-stat.go.jp/rest/3.0/app/json/getStatsList?appId=...
```

`appId` (アプリケーション ID) が要る。無しで投げると HTTP 200 のまま
`{"RESULT":{"STATUS":100,"ERROR_MSG":"認証に失敗しました。アプリケーションIDを確認して下さい。"}}`
が返る。ステータスコードは 200 なので、HTTP の層だけ見ていると成功に見える。

手元では `Geo-Voyager` が `src/lib/common/getEStatLatestPopulationOfPrefs.ts` で
`process.env.E_STAT_APP_ID` を使い、`getStatsData` に `statsDataId=0000010101`
(社会・人口統計体系) を渡している。ID が未設定なら例外を投げる形になっている。

2026-09-30 時点で、この環境に appId は置かれていない。API を使うには先に取得する必要がある。

出典の書き方、適用外のものについては

境界データに限った話ではなく、e-Stat のコンテンツ全体に同じ規約が当たる。

統計 LOD だけは VoID の中で `dcterms:license <http://creativecommons.org/licenses/by/4.0/>` と
機械可読に宣言している ([lod.md](lod.md))。規約ページの「CC BY に従うことでも利用することができます」
という間接的な書き方ではなく、CC BY 4.0 そのものを指している。同じ組織の同じデータでも、
経路によってライセンスの書かれ方が違う。

## 取り出し方

区分は catalog と split の組み合わせ。`search_detail` で欲しい配布物を絞り込んでから、
都道府県または市区町村の単位で引く。

| 段階 | 手段 | 実測 |
|---|---|---|
| 目録 | `search_detail` の JSON | 境界データ 54 件を認証なしで列挙できた |
| 分割 | `code` に 2 桁 (都道府県) か 5 桁 (市区町村) | 東京都 5,682,172 バイト、台東区 45,783 バイト |
| 部分 | Range は効かない | `curl -r 0-1023` が 206 ではなく 200 で全体を返す |

`accept-ranges: bytes` を返すのに Range が効かない件は
[estat-boundary/README.md](../estat-boundary/README.md) の取り出し方の節に測定が残してある。

全部を手元に置く場合の見積もり。境界データが約 10.8GiB。統計データ側の
メッシュ統計は測っていないので未確認。

## 境界データを GeoParquet にして分かったこと

2026-10-01 に、境界データを取得して GeoParquet にするスクリプト [scripts/mirror_estat_boundary.py](../../../scripts/mirror_estat_boundary.py) (テストは [tests/test_mirror_estat_boundary.py](../../../tests/test_mirror_estat_boundary.py)) を作ったときに確かめたこと。

### 目録 (boundary-catalog.tsv) の訂正

tsv は測ったときのまま残し、ここに訂正を書く。

- 国勢調査 2020 年の基本単位区 (`B002005212020`) の 8,111 バイトはデータではない。この URL は JGD2000 版でも JGD2011 版でも、47 都道府県すべてで zip ではなく 404 の HTML ページ (8,111 バイト) を返した。存在しない組み合わせ (国勢調査 2000 年の JGD2011 版) を要求したときと同じページ。基本単位区の取り方は分かっていない。
- 事業所・企業統計調査 2001 年 (`A002005512001`) は 12 都道府県しか無い。北海道、宮城、埼玉、千葉、東京、神奈川、愛知、京都、大阪、兵庫、広島、福岡。残りの 35 は HTTP 200 で 22 バイトの空の zip が返った。`search_detail` の目録もこの 12 しか載せていないので、欠けは配布元にもともと無いもの。
- 農林業センサスの種類違いは、少なくとも 2020 年の東京都では中身が同じ。農林業経営体、農業経営体、農業経営体 (個人経営体) の 3 つで、展開した .shp と .dbf の md5 が一致した。zip の md5 が違うのは、配布元が要求のたびに zip を作り直し、メンバーの時刻が要求した時刻になるから。2005 年と 2010 年の 5 種類は、47 都道府県の合計の大きさがそれぞれ 94,276,169 バイトと 143,444,093 バイトでバイト単位まで一致した。中身の一致は東京都の 2020 年でしか確かめていない。スクリプトは中のファイルの名前と中身で比べ、47 都道府県すべてで一致したものを 1 か所にまとめる。
- 合計の大きさ (47 都道府県、JGD2000) の実測。国勢調査の小地域は 2000 年 304,351,976、2005 年 310,488,078、2010 年 314,237,988、2015 年 317,477,492、2020 年 322,733,398 バイト。経済センサスは 1 件 756〜766MB。

### 変換で確かめたこと

- GDAL の Shapefile ドライバ (DuckDB spatial の `ST_Read`) では dbf を読めなかった。`open_options=['ENCODING=CP932']` を渡しても、SJIS などの別名でも、anaconda の GDAL の環境変数を外しても、`Invalid unicode (byte sequence mismatch)` で止まる。DuckDB spatial のもう 1 つの読み取り関数 `ST_ReadSHP(path, encoding := 'blob')` なら、文字の列をバイト列のまま返し、数値の列は dbf の型で返す。スクリプトはこれを Python の cp932 で厳密に解き、解けない値があれば止まる。
- DuckDB 1.5.5 は CRS を型に持てる (`GEOMETRY('EPSG:4612')`)。これで書いた Parquet の GeoParquet メタデータには `crs` が入る (JGD2000 は EPSG:4612、JGD2011 は EPSG:6668)。
- 国勢調査 2020 年の小地域は全国で 232,019 行。`yuiseki/estat-boundary-2020` の `provenance.yaml` の数と一致した。JINKO の合計は 126,146,099。1 ファイル 318MB で、分割は要らない。
- JGD2011 版は座標が本当に違う。都道府県ごとの重心の平均を比べると、宮城県は東へ約 0.14 秒 (約 3.5m)、福島県は約 0.08 秒ずれ、北海道、東京都、大阪府、沖縄県はずれていない。ところが代表点の属性 `X_CODE` は宮城県でも差が 0 だった。JGD2011 版の X_CODE と Y_CODE は JGD2000 の値のまま残っているように見える。JGD2011 版で代表点が要るときは、属性ではなくジオメトリから計算する。
- 版をまたいで行の並びが違う。JGD2000 版と JGD2011 版を行番号で突き合わせることはできない。
