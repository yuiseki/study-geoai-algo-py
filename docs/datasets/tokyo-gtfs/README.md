# 東京 23 区のバスの GTFS

2026-09-28 に探して、取れたものは中身を数えた。台東区めぐりんは [odpt-taito-megurin](../odpt-taito-megurin/README.md) に別にある。

## 探した場所

- 公共交通オープンデータセンター (ODPT) のカタログ <https://ckan.odpt.org/>。組織 119 のうち、23 区の区として出しているのは台東区、中央区、杉並区だけだった。ほかに事業者として東京都交通局 (都営バス) と国際興業がある。
- GTFS データリポジトリ <https://gtfs-data.jp/> の API (`https://api.gtfs-data.jp/v2/files?pref=13`、応答は gzip)。東京都のフィードは 10 で、23 区は荒川区と葛飾区の 2 つ。残りは多摩と島しょ (国立市、昭島市、立川市、瑞穂町、小笠原村、神津島村)。

この 2 か所に無い区のコミュニティバス (文京区、港区、千代田区、渋谷区など) は、ほかの場所で公開されているかもしれない。探していない。

## 登録が要るもの (使わない)

- 中央区 江戸バス (<https://ckan.odpt.org/dataset/tokyo_chuo_city_alldata>): 開発者サイトでの登録が要る。ライセンスは公共交通オープンデータ基本ライセンス (CC BY 4.0 ではない)。有効期間 2026-07-15〜2028-06-30。
- 国際興業: ODPT にあるのは時刻表、路線、停留所の API 形式のデータセットで、GTFS は見当たらなかった。

## 気をつけること

- 4 つとも `trips.txt` の `block_id` が空。どの車両がどの便を走るかは書かれていない。
- 荒川区と葛飾区は、時の桁が 0 で埋められていない時刻が混ざる (荒川区は 568 件中 248 件、葛飾区は 684 件中 156 件。例: `6:50:00`)。GTFS の仕様では 1 桁も許されているが、文字列のまま比べたり並べたりすると順番が狂う。どちらも feed_version に同じ作成ツール (西沢ツール) の名前がある。秒に直してから扱う。
- 都営バスの feed_version は `20260928_030815` で、URL に日付が入っていない。中身は日々差し替わると見られるので、使うときは feed_version を記録する。
- ODPT の公開 URL は HEAD 要求に 404 を返す。GET なら 302 のあと 206 で取れる。
- 都営バスは 72 の service_id (曜日と例外の組み合わせ) を持つ。

## 学習ステップとの対応 (案)

- 10 CP-SAT / scheduling:
  - A (台東区): めぐりん 290 便。
  - B (23 区): 都営バス 55,846 便。1 日分と 1 営業所分に絞っても、めぐりんより桁違いに大きい。同じ解き方がどこまで大きな問題に通用するかを見る。
  - 小さい例として、荒川区 34 便、葛飾区 57 便、杉並区 24 便も使える。最初に手で解いて答えを確かめる題材になる。
- 7 Dijkstra / A*: 都営バスの停車時刻から、23 区の時刻付きのグラフを作る。

## z.yuiseki.net のミラー

再現できるように、めぐりんを含む 5 つのフィードを、2026-09-28 に取得したまま (中身を変えずに) <https://z.yuiseki.net/static/gtfs/> に置いた。どれも CC BY 4.0 なので、クレジットを付ければ再配布できる。

- パスは `<取得元>/<公開元>/<フィード>/<版>/<元のファイル名>`。版は ODPT なら URL の `date`、都営バスは feed_version、gtfs-data.jp はファイルの uid。版ごとにディレクトリを分けたので、同じパスはいつも同じ中身を返す。
- 取得元の URL、取得日時、大きさ、sha256、feed_version、有効期間はミラーの README.md に、ODPT の FAQ の書式に沿ったクレジットは LICENSE に書いた。
- 公開 URL から落とした 5 つの sha256 が、取得したときの値と一致することを確かめた。
- `study_geoai.gtfs.load(con, "toei")` のように、ミラーから読んでフィードごとのスキーマ (`toei.trips` など) を作る。
