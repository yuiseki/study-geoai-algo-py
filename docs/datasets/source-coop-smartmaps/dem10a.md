- Web ページの題は「Japan GSI 1m GSD Terrain Tiles in PMTiles」。

## 中身 (PMTiles のヘッダとディレクトリを Range 要求で読んだ)

- PMTiles v3、タイル形式 WebP (512x512、RGB)、タイル圧縮なし、clustered。
- ズーム 3 から 17。タイル数 111,853 (z17 が 83,659、z16 が 21,060、z15 が 5,304)。
- 実際にタイルがある範囲の外接矩形 (z17 のタイル座標から計算): 経度 140.875 から 141.614、緯度 37.998 から 38.668。座標から見ると宮城県の仙台周辺で、全国ではない。
- エンコーディング: Mapbox Terrain-RGB と読むと値が妥当になる。`elevation = -10000 + (R*65536 + G*256 + B) * 0.1`。z10 の 1 タイルで -1.6 から 341.8 m、海の画素は RGB (1,134,160) で 0.0 m。Terrarium と読むと -32,377 m 前後になり、合わない。

## 気づいたこと

- ヘッダの bounds と center が全部 0。メタデータは `{"description":"","format":"webp","name":"","type":"baselayer","version":"1"}` だけで、範囲もエンコーディングも書かれていない。
- 名前は dem10a だが Web ページの題は「1m GSD」。どちらが正しいかは未確認。元が国土地理院の DEM10A か DEM1A かは確かめられなかった。
- 作り方の説明は無い。

## ライセンス

未確認。書かれているのは国土地理院の測量法に基づく使用承認番号 (R 6JHs 133) だけで、再配布条件は書かれていない。

## 学習で使うなら (案)

- 範囲が仙台周辺に限られるので、全国の特徴量には向かない。小さい地域で試すなら使える。
- ステップ 1 から 3: 標高、傾斜を地点の特徴量にする (デコードして画素を引く)。
- ステップ 7: 傾斜をコストにした Dijkstra / A* の格子グラフ。
- 全国なら japan-geotiff-dem のほうが素直 (GeoTIFF で値がそのまま入っている)。
