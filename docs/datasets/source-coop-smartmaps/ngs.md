# ngs

2026-09-28 に読んで確かめた内容。

- `https://source.coop/smartmaps/ngs` (Web ページの題は「Smart Maps LiDAR 3D Tiles from Open Nagasaki」)
- データの URL は `https://data.source.coop/smartmaps/ngs/<key>`。入口は `ngs/tileset.json`

## 何のデータか

Web ページの説明によると、UN Smart Maps Group が Open Nagasaki (`https://opennagasaki.nerc.or.jp/`) の LiDAR データ全部から 1 つの 3D Tiles (点群) を作ったもの。「まだ作業中 (work in progress)」とある。デモは `https://observablehq.com/d/c4d563b1731f286f`。

- Web ページの作成日は 2024-04-14、最終更新は 2025-08-21。
- ファイルの更新日時は 2024-04-14 から 2024-04-19 (数えた範囲で)。
- 元データの版や計測年、どのツールで 3D Tiles にしたかは、読んだ範囲には書かれていなかった。

## 形式と大きさ

3D Tiles 1.0 の点群 (pnts) と、分割された tileset JSON。

一覧を `delimiter=/` で取ると、直下のファイルとサブディレクトリが 20 秒で取り切れた:

| 場所 | 実測 |
|---|---|
| 直下のファイル | 17,030 個、2,307,365,264 バイト (pnts 13,355 個、json 3,675 個) |
| 直下のサブディレクトリ | 4,940 個 (すべて 8 桁の数字) |

サブディレクトリの中身は、continuation-token をたどる一覧で 58.7 秒かけて 64,000 個 (9,080,350,168 バイト、すべて pnts) まで数えたところで打ち切った。このとき進んだのは 4,940 ディレクトリのうち先頭 241 個 (`ngs/11157733/` の途中まで)。

- 合計は 81,030 ファイル以上、11,387,715,432 バイト (11.39GB) 以上。全体の件数は 60 秒では数えきれなかった。
- pnts の大きさ: 直下は最小 120 バイト、中央値 116,664 バイト、最大 328,664 バイト。サブディレクトリ (数えた 64,000 個) は最小 1,760、中央値 142,376、最大 355,256 バイト。
- json の大きさ: 100,101 から 453,100 バイト。
- 0 バイトのファイルは数えた範囲では無かった。

並び方 (tileset を読んで確かめた):

- ノード名は `r` の後に 0 から 7 の数字を 1 階層 1 桁で足していく八分木 (例 `r.pnts`, `r2.pnts`, `r26.pnts`, `r264.pnts`)。
- 深い階層は、先頭 8 桁を名前にしたサブディレクトリへ移る。`tileset.1111.json` の中で `r11111337.pnts` の子が `11111337/r1.pnts`, `11111337/r3.pnts` と参照されていた。
- 分割された tileset は `tileset.<数字>.json` (例 `tileset.1.json`, `tileset.2642.json`)。親の tileset から `content.uri` で参照される。
- サブディレクトリ名に使われている数字は 5, 1, 3, 7 が多く、6, 2, 4, 0 は少ない (出現数 5: 11,603、1: 10,062、3: 8,518、7: 7,764、6: 866、2: 481、4: 119、0: 107)。

## 中身

### tileset.json (172,374 バイト)

- `asset.version` は 1.0。`geometricError` は 294578.63。
- root は `box` の境界と `transform` を持ち、`refine` は REPLACE、content は `r.pnts`。
- transform の 3 列はどれも長さ 100.0 (100 倍に拡大)。平行移動は ECEF で (-3390241.1, 4126580.9, 3475022.4)、緯度経度にすると 東経 129.405、北緯 33.227。
- root の box の四隅 (高さは中心の値) を緯度経度にすると、経度 128.57 から 130.41、緯度 32.55 から 34.73。長崎県の本土、五島、対馬が収まる範囲。box は境界の直方体なので、実際に点がある範囲より広い可能性がある (点の範囲は確かめていない)。
- この tileset.json の中にはノードが 718 個 (深さ 0 から 12)、pnts の参照 676 個、外部 tileset の参照 36 個。

### pnts

代表 4 件を全体ダウンロードして、28 バイトのヘッダと feature table を読んだ。

| ファイル | 大きさ | POINTS_LENGTH | feature table |
|---|---:|---:|---|
| `r.pnts` | 4,384 | 285 | POSITION, RGB |
| `r0.pnts` | 120 | 1 | POSITION, RGB |
| `11111337/r1.pnts` | 288,464 | 19,223 | POSITION, RGB |
| `11131351/r111.pnts` | 245,872 | 16,384 | POSITION, RGB |

- 4 件とも magic `pnts`、version 1、batch table は空 (JSON 0 バイト、バイナリ 0 バイト)。
- POSITION は FLOAT32 の 3 成分、RGB は 1 成分 1 バイト。RTC_CENTER や量子化 (POSITION_QUANTIZED) は使っていない。
- 分類コード、反射強度、リターン番号は入っていない。点が持つのは位置と色だけ。
- 位置はローカル座標で、root の transform (100 倍と ECEF への平行移動) を掛けて地球上の位置になる。例えば `11111337/r1.pnts` の範囲はローカル単位で X 約 1.8、Y 約 1.4、Z 約 0.03 (100 倍するとおよそ 180m × 140m × 3m)。

## 気づいた異常

- `r0.pnts` は点が 1 個だけ (120 バイト)。八分木の上の階層には点がごく少ないノードがある。
- S3 一覧の `start-after` の挙動がおかしい。`start-after=ngs/11131351/r1111.pnts` を渡すと、残りのサブディレクトリを飛ばして直下の `ngs/r.pnts` から返ってきた。件数を数えるときは `start-after` を使わず continuation-token だけでたどること。
- Web ページに「work in progress」とある。欠けている区域があるかは確かめていない。

## 12 ステップでの使い道 (案)

- 5 k-means/DBSCAN: XYZ と RGB だけの点群なので、ラベルなしのクラスタリングの練習台になる。1 タイル 1 万から 2 万点程度で扱いやすい。
- 6 PCA: 近傍点の共分散から地表面の向きや平面らしさを出す。
- 1 線形回帰: 小さい範囲の点に平面をあてはめ、地表の傾きを推定する。
- 4 Cross Validation とデータリーク: refine が REPLACE なので、親ノードは同じ場所の点を間引いたものと考えられる (推定)。親子を訓練と評価に分けるとリークになりうる。使う階層を決めてから分ける。
- 分類の正解ラベルが無いので、2 や 3 の教師あり学習には別のラベル (例えば xing の建物形状) と重ねる必要がある。
