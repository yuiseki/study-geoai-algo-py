# japan-geotiff-dem

2026-09-28 に読んで確かめた内容。

- `https://data.source.coop/smartmaps/japan-geotiff-dem/`
- `README.md` (7,641 バイト、更新 2026-08-24) あり。source.coop の Web ページの題は「Japan GeoTIFF DEM for Mapterhorn」。
- 国土地理院の基盤地図情報 DEM (GML の zip) を GeoTIFF に変換したもの。変換は [`optgeo/japan-geotiff-dem`](https://github.com/optgeo/japan-geotiff-dem)。発行は UN Smart Maps Group。
- 解像度別に 3 つの接頭辞: `1/` (1m)、`5/` (5m)、`10/` (10m)。直下には `README.md` だけ。
- 1 ファイル = 国土地理院のメッシュ 1 つ。名前は国土地理院のまま `FG-GML-<1次>-<2次>-<3次>-<種別>-<測量日YYYYMMDD>.tif` (10m は 3 次が無く `FG-GML-<1次>-<2次>-<種別>-<日付>.tif`)。
- mapterhorn-japan-bridge の入力。

## 気づいたこと

- 同じメッシュに測量日違いのファイルが複数ある (新しい測量が別ファイルで追加される)。使う前に `latest_file_list.csv.gz` で絞るのが前提。
- 10m の latest の中にも同じ 2 次メッシュが 96 組、DEM10A と DEM10B の両方で入っている (例: `FG-GML-4429-35-dem10a-20161001.tif` と `FG-GML-4429-35-dem10b-20161001.tif`)。種別が違うので重複ではないが、1 メッシュ 1 行ではない。
- 種別の大文字小文字が揺れる (`DEM10B` / `dem10b` / `dem10B`、`DEM5B` / `dem5b`)。README はファイル名が国土地理院の命名に従うと書いているので、元の名前から来た揺れかもしれない (未確認)。照合は大文字小文字を無視する。
- `1/.gitkeep` と `5/.gitkeep` が 0 バイト。
- README の変更履歴に、長崎周辺 (1 次メッシュ 4929/4930) の 1m ファイルで変換ツールの不具合により中身が壊れていたものを 2026-08-22 から 08-25 に直した、とある。
- 5m と 10m は有効画素が少ないタイルが多い (海や測量範囲外は -9999)。

## ライセンス

README の記載: 「測量法に基づく国土地理院長承認（複製）R8JHf51」。不特定多数に提供するために複製する場合は国土地理院の長の承認が必要、と書かれている。変換物そのもののライセンス (CC0 など) は README には書かれていない (未確認)。

## 学習で使うなら (案)

- 全国を GeoTIFF の数値のまま引けるので、地形特徴量の元として一番扱いやすい。まず 10m (4,981 件、約 4.6GB) で試し、狭い範囲だけ 1m に上げる。
- ステップ 1 から 3: 地点の標高、傾斜、起伏量、斜面の向きを特徴量にする (土砂災害、浸水、植生などの目的変数と組み合わせる)。
- ステップ 4: 隣り合うメッシュが似るので、メッシュ単位の空間ブロック CV にする題材になる。
- ステップ 5 と 6: 地形指標の多変量を k-means や PCA で地形区分に。
- ステップ 7: 傾斜コストの格子グラフで Dijkstra / A*。
- ステップ 9: 施設配置の候補地を標高や傾斜で絞る制約に。
