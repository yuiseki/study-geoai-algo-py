# adopt-hokkaido-lidar

2026-09-28 に読んで確かめた内容。

- `https://source.coop/smartmaps/adopt-hokkaido-lidar` (Web ページの題は「Hokkaido Aerial LiDAR (COPC)」)
- データの URL は `https://data.source.coop/smartmaps/adopt-hokkaido-lidar/<key>`
- 変換パイプラインは GitHub の `optgeo/adopt-hokkaido-lidar`

## 何のデータか

北海道庁が実施した航空レーザ測量の LAZ を、1 ファイルずつ COPC (Cloud Optimized Point Cloud) に変換したもの。Web ページの説明によると:

- 元データは G空間情報センター (geospatial.jp) と、酪農学園大学が運営する ArcGIS Hub のオープンデータポータルから取得している。
- 測量機関の「ORIGINAL」の .laz 1 個に COPC 1 個が対応し、マージはしない。
- 帰属表示とライセンスは測量案件ごとに記録している (部局は総合政策部、水産林務部など)。ライセンスは「これまで確認できたものはすべて CC-BY」。来歴とライセンスが確認できた案件だけを公開している。
- 元の ZIP や LAZ は置いておらず、検証済みの COPC だけを置いている。
- Web ページの作成日と更新日はどちらも 2026-09-09。

ファイルの更新日時は 2026-09-09 から 2026-09-15。

## 形式と大きさ

| 項目 | 実測 |
|---|---|
| ファイル数 | 3,541 (laz 3,539、pmtiles 1、jsonl 1) |
| 合計 | 199,687,590,553 バイト (199.69GB) |
| laz の大きさ | 最小 1,782 バイト、中央値 62,137,982 バイト、最大 191,445,665 バイト |
| 0 バイトのファイル | なし |

並び方:

```
adopt-hokkaido-lidar/
  catalog/index.pmtiles        1,301,019 バイト
  catalog/manifest.jsonl         767,746 バイト、3,538 行
  data/arcgis/<ArcGIS の item ID 32 桁>/<図郭名>/v<版>/<図郭名>.copc.laz
```

- `data/` の下は `arcgis/` だけだった。Web ページは geospatial.jp も取得元に挙げているが、geospatial.jp 由来のディレクトリは見当たらない。
- ArcGIS の item ID は 273 個。1 item あたり 1 から 16 ファイル。
- 図郭名はすべて `12` + 英字 2 文字 + 数字 4 桁 (例 `12he5944`)。英字 2 文字は 9 種類 (ie 1,009、if 929、he 712、je 239、hd 238、hf 143、jf 129、id 107、jd 33)。同じ図郭名が複数の item に出ることはなかった。
- 版のディレクトリは v1 2,750、v2 554、v3 158、v4 45、v5 22、v6 4、v8 4、v7 1、v9 1。1 図郭に置かれている版は 1 つだけで、古い版は残っていない。

## 中身

### LAZ (COPC) のヘッダ

先頭 64KB を Range 要求で読み (206 を確認)、Python 標準ライブラリで LAS ヘッダと VLR を解析した。代表 5 件:

| 図郭 | 点数 | X 範囲 | Y 範囲 | Z 範囲 |
|---|---:|---|---|---|
| 12jf0612 (最小ファイル) | 16 | 65000.28 から 65003.50 | 29981.95 から 29996.51 | 406.74 から 409.51 |
| 12he5944 | 385,931 | 39336.50 から 40000.00 | 72000.00 から 72313.56 | 174.47 から 345.95 |
| 12je1411 | 448,887 | 16000.00 から 16897.66 | 26684.06 から 27000.00 | 135.00 から 208.11 |
| 12ie0711 | 6,965,311 | 28000.00 から 29000.00 | 59250.00 から 60000.00 | 314.94 から 461.79 |
| 12ie0022 (最大ファイル) | 18,371,696 | 3000.00 から 4000.00 | 59250.00 から 60000.00 | 115.84 から 323.62 |

5 件に共通していたこと:

- LAS 1.4、System ID は PDAL、Generating Software は PDAL 2.10.2。作成日は 2026 年の通日 252 から 258。
- 点フォーマット 7 (1 点 36 バイト。RGB と GPS 時刻を持つ形式)。
- スケール 0.01 (X, Y, Z)、オフセット 0。
- VLR は 3 個。COPC info VLR、laszip の VLR (lazperf variant)、OGC WKT の CRS。
- CRS の WKT は `JGD2000 / Japan Plane Rectangular CS XII` で、EPSG は 2454 (平面直角座標系 第 XII 系)。
- リターン番号別の点数が 1 から 5 まで入っている (例 12ie0711 は 2,771,943 / 2,070,457 / 1,274,206 / 586,631 / 199,246)。
- 1 図郭いっぱいのファイルは X 方向 1,000m、Y 方向 750m (12ie0711、12ie0022)。範囲が端で欠けているもの (12he5944、12je1411) は測量範囲の境界にかかる図郭と思われる (推定)。

分類コード (classification) の分布は点データを展開しないと読めないため、確かめていない。LAZ の展開には laspy と lazrs (または PDAL) が要る。依存は追加していない。

### catalog/manifest.jsonl

3,538 行。各行は `asset_id` と `object_url` の 2 キーだけ。Web ページは「各アセットのメタデータで帰属を確認すること」と書いているが、manifest には帰属やライセンスの欄は無かった。

### catalog/index.pmtiles

全体をダウンロードして (1.3MB) ヘッダとメタデータを読んだ。

- PMTiles v3、ベクトルタイル (pbf)、z0 から z14、タイル 1,390 個。
- tippecanoe v2.79.0 で生成。レイヤは `footprints` (Polygon 3,538 個)、属性は `asset_id` だけ。
- 範囲は経度 142.12328 から 143.24131、緯度 44.157877 から 44.789634。北海道の北部にあたる (どの市町村かは照合していない)。

## 気づいた異常

- laz は 3,539 個あるのに、manifest.jsonl と index.pmtiles は 3,538 件。差の 1 件は `data/arcgis/fb8559df347e43e68f9634dbc17d9f6f/12je1411/v1/12je1411.copc.laz` (ヘッダは正常に読めた。点数 448,887)。
- `12jf0612.copc.laz` は 1,782 バイトで点が 16 個しかない。極端に小さいファイルは他にもある (1,894、1,979、2,017、2,877 バイト)。
- CRS の表記は JGD2000。元データが JGD2000 なのか、変換時の指定なのかは確かめていない。JGD2011 の他データと重ねるときは注意。
- GitHub の README は「まだ 1 件も COPC 変換・公開はしていない」と書いたままで、実際の公開状況と合っていない。

## ライセンス

- Web ページでは、ライセンスは測量案件ごとに違い、「これまで確認できたものはすべて CC-BY」とある。
- ファイルごとのライセンスと帰属表示は、今回読んだ manifest.jsonl と index.pmtiles には無かったため、ファイル単位では未確認。
- パイプラインのコードと文書は CC0 1.0 (GitHub の README)。点群そのものは提供元のライセンスに従う、とある。

## 12 ステップでの使い道 (案)

- 2 Decision Tree/Random Forest、3 Gradient Boosting: 点ごとの特徴量 (高さ、リターン番号、RGB、近傍の統計) から地表や植生を分類する。分類コードが入っていれば正解ラベルに使える (未確認)。
- 4 Cross Validation とデータリーク: 隣り合う図郭の点はよく似ているので、ランダム分割ではなく図郭単位や item 単位で分ける練習になる。
- 5 k-means/DBSCAN: 地表以外の点を DBSCAN でまとめて、樹木や建物の塊を取り出す。
- 6 PCA: 近傍点の共分散の固有値から平面らしさや線らしさを出し、法線を求める。
- 7 Dijkstra/A*: 地表点から作った標高グリッドで、勾配をコストにした経路探索。
- 1 ファイル 60MB 前後が中央値なので、最初は 12jf0612 のような小さいものか、COPC の上位階層だけを Range で読む形が扱いやすい。
