# un-docs

2026-09-28 に読んで確かめた内容。

- `https://huggingface.co/datasets/yuiseki/un-docs`
- 国連の総会 (`A/...`) と安全保障理事会 (`S/...`) の文書の英語本文を、1 文書 1 行にしたもの。PDF のテキスト層から取ったものと、スキャン画像を tesseract で読んだものがある。
- 位置の列 (座標、国) は無い。地名は本文の中にしか無い。
- 作ったコード: `https://github.com/yuiseki/undocs`。

## 元データと基準日

- `https://docs.un.org/{lang}/{symbol}` の PDF。`provenance.yaml` によれば 2026-09-15 より前に取得。文書記号の一覧は un.org のページから集めた 41,942 URL (正規化後 39,405 記号)。
- 抽出は pdftotext 24.08.0、スキャンは tesseract 5.5.0 (300 dpi)。
- `provenance.yaml` の `built` は 2026-09-21。Hugging Face の最終更新も 2026-09-21。
- 文書の日付は 1945-08-08 から 2023-10-16 (実測、3 つの日付列のどれかがある文書で)。

## 列

| 列 | 型 | 中身 (カードの説明) |
|---|---|---|
| `id` | VARCHAR | 文書記号 (例 `A/1251`) |
| `lang` | VARCHAR | ISO 639-1 |
| `body` | VARCHAR | 抽出した本文 |
| `text_source` | VARCHAR | `pdf` か `ocr` |
| `pdf` | VARCHAR | リポジトリ内の PDF のパス |
| `date_distributed`, `date_adopted`, `date_other` | VARCHAR | ISO 8601 の日付 (文字列) |

| `n_chars` | BIGINT | `body` の長さ |

日付は DATE 型でなく文字列。実測では全部 `YYYY-MM-DD` の形だった。

## ライセンス

- カードとタグは `other` (`license_name: united-nations-parliamentary-documentation`, `license_link: https://shop.un.org/rights-permissions`)。
- `LICENSE` の中身: 国連の議事文書 (parliamentary documentation) と、文書記号を持ち販売されていない広報資料は国連の著作権の対象外で、パブリックドメインとする。抽出した本文は機械的な書き起こしで著作性を加えず、集めたことで生じうる権利も放棄する。許可も表示も不要だが、出典として国連を示すのが礼儀、とある。
- この扱いが国連の規程として正しいかは、`https://shop.un.org/rights-permissions` を読んでいないので未確認。

## 気づいた異常

- カードの日付の件数表が実物と合わない。カードは `date_distributed` 19,283、`date_other` 16,695、`date_adopted` 8,206 だが、実測は 19,441、18,227、8,227 で、`provenance.yaml` の数と一致する。両方ある文書もカードは 7,517、実測は 7,528 (値が違う 4,575 は一致)。
- `provenance.yaml` の中でも食い違う。日付抽出の注記は「両方ある 2,249 件のうち 315 件が食い違う」と書き、カードの 7,517 件と 4,575 件と合わない (古い版の注記が残っていると見える)。
- `provenance.yaml` の既知の制限に「A/RES/981(X) の OCR が悪い。残り 4,023 は綺麗」とあり、OCR した 1,864 件とも総数 39,363 とも合わない (4,073 件だった頃の記述と見える)。同じく「2020 年から 2023 年に偏っている」とあるが、実測の 2020 年代は 3,709 件で、2000 年代と 2010 年代のほうが多い。
- カードの例 `S/RES/2728 (2024)` の 2024 年の文書は入っていない (日付の最大は 2023-10-16、記号に `(2024)` を含む行も 0)。カードの「1945 年から 2023 年」とは合っている。
- `pdf` は全行に値があるが、カードによればリポジトリに PDF があるのは 4,073 件だけ。パスがあっても PDF があるとは限らない。
- カードの列の表では `n_chars` が `body` の直後だが、実物では最後の列。

## 12 ステップでの使い道 (案)

位置の列が無いので、このままでは地理の点データにならない。

- 本文を `wikidata-gazetteer` の名前と突き合わせて地名を拾えば、文書と国の対応表 (文書ごとに言及された国の数など) を作れる。ただしこれは文字列照合の前処理で、カードも誤検出が多いと書く。study-geoai の範囲では優先度は低い。
- 1 ロジスティック回帰: 文字数と年から `text_source` (pdf か ocr) を当てる、`id` の頭 (総会か安保理か) を当てる、といった表形式の小さな練習にはなる。地理とは関係ない。
- 4 データリーク: 同じ会期の文書が学習と検証に割れる、時系列の分け方の題材にはなる。
- 5 から 12 には使えない。
