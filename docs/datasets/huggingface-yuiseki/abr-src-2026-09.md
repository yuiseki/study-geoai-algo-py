# abr-src-2026-09

2026-09-28 に読んで確かめた内容。

- <https://huggingface.co/datasets/yuiseki/abr-src-2026-09>
- デジタル庁のアドレス・ベース・レジストリ (住所の基本台帳) のうち、都道府県・市区町村・町字のマスターと代表点を 2026-09-26 に固めたもの。境界 (ポリゴン) は無く、代表点だけ。
- 最終更新 2026-09-26。
- 元の CSV の zip (53 個、配布元のまま) も csv/ に置いてある。

- 列はすべて VARCHAR (Parquet の StringType)。緯度経度 (rep_lon, rep_lat) も文字列。lg_code 011011 や machiaza_id 0000101 の先頭のゼロを守るため (カードの説明どおり)。
- 行グループはどれも 1 つ。

## 列 (主なもの)

- mt_town_all: lg_code, machiaza_id, machiaza_type, pref / county / city / ward / oaza_cho / koaza と、それぞれの _kana, _roma、chome, chome_kana, chome_number, rsdt_addr_flg, efct_date, ablt_date, post_code, remarks など 38 列。
- mt_town_fullset_all: 上に外字関係などの 14 列を足した 52 列。
- mt_town_pos_all: lg_code, machiaza_id, rep_lon, rep_lat, rep_srid, rep_scale、ポリゴン関係 (plygn_*)、cns_bnd_s_area_kcode, cns_bnd_year など 18 列。

## 中身

- 町字 (mt_town_all) の machiaza_type: 1 (大字・町) 106,479、2 (丁目) 94,505、3 (小字) 526,344、4 が 70、5 が 31。
- 名前の埋まり方で数えると、小字あり 526,344、丁目ありで小字なし 94,512、どちらも無し 106,573。カードの「丁目 94,512」「小字 526,344」はこの数え方と一致する。
- post_code が入っている行 93,698。
- efct_date は 1947-04-17 〜 2026-09-05。
- 代表点 (mt_town_pos_all) の範囲は経度 122.94〜153.98、緯度 20.43〜45.52。数値にできない値は無い。
- 町字と代表点を (lg_code, machiaza_id) で結ぶと、代表点を持つ町字は 196,161 (異なるキー数)、町字側に相手のいない代表点が 128,310 行。どちらもカードと一致する。
- 市区町村 (mt_city_all) のうち郡に属するもの 923、郡は 373。

## 気をつけること

- 町字の行数はカードの 727,428 より 1 多い 727,429。多い 1 行は ablt_date (廃止日) が 2026-10-12 と未来の日付になっている行 (lg_code 152188、村松)。カードの数は廃止予定のこの行を除いて数えたように見える (大字・町 106,572 と 106,573、郵便番号 93,697 と 93,698 も同じく 1 ずれる)。
- mt_town_all の (lg_code, machiaza_id) は一意ではない。2 回出るキーが 1,248 あり (43 都道府県、210 市区町村)、行としてはすべて異なる。例は札幌市の「南９条西 ５丁目」。どの列が違うかは確かめていない。
- mt_town_pos_all には完全に同じ行の重複がある。337,641 行のうち異なる行は 324,471 (provenance.yaml の position_keys と一致)。DISTINCT してから使う。
- 代表点の測地系が混ざっている。rep_srid は EPSG:4612 (JGD2000) が 208,501 行、EPSG:6668 (JGD2011) が 129,140 行で、47 都道府県すべてに両方がある。カードには書かれていない。経緯度の差は小さいと思われるが、測っていない。
- ポリゴンの列 (plygn_fname など) は全行空。cns_bnd_s_area_kcode (国勢調査の小地域キー) と cns_bnd_year も全行空なので、estat-boundary-2020 とこの列で結ぶことはできない。
- ファイルごとに版が違う。町字の名前は 2026-09-25、町字の代表点は 2025-10-27、都道府県と市区町村は 2024-03。
- Hugging Face のタグの件数区分は 1M-10M だが、カードの YAML は 100K-1M。

## 他のデータセットとの関係

- jp-admin-2026-09 のコード、名前 (漢字・かな・ローマ字)、郡と区の構造、代表点はここから取られている。
- estat-boundary-2020 とは市区町村までは lg_code の先頭 5 桁で結べる。町字は名前の照合になる。

## 12 ステップで使えそうな場面 (案)

- 主な用途は地名辞典 (どの町字がどの市区町村にあるか、読み方)。表形式の機械学習の目的変数になる数値はほとんど無い。
- 5 k-means/DBSCAN: 町字の代表点 (重複を除いた約 32 万点) を点群にして密度クラスタリングする。市区町村ごとに代表点の散らばりを比べるくらいはできる。
- 9 facility location: 候補地や需要点の座標として使えるが、需要量 (人口) は無いので estat-boundary-2020 か jp-admin-2026-09 と組み合わせる。
- それ以外のステップでは、他のデータに市区町村コードや名前の読みを付ける補助として使う。
