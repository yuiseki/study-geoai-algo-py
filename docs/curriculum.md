# カリキュラム: 台東区 (A) と東京 23 区 (B)

12 ステップを、台東区と東京 23 区の 2 つの範囲で進める。データはすべて [docs/datasets/](datasets/README.md) で確かめたもの。

## 2 つの範囲の役割

| | A 台東区 | B 東京 23 区 |
|---|---|---|
| 目的 | 小さく速く回し、結果を地図で目で確かめる | 規模を上げ、ほかの場所でも通用するかを試す |
| 使い方 | まず A で全部を動かす | A で動いたコードを、範囲だけ変えて B で回す |
| つなぎ | 4 番で「22 区で学習して台東区で試す」評価をする | 同左 |

A で動かしてから B に広げる。変えるのは範囲だけにして、コードは同じものを使う。

A では小さすぎる題材もある。Ookla の速度タイルは約 610m 四方なので、台東区 (約 10km²) だけでは数十枚しかない。そういうものは B を主にする。

## 0. 共通の下ごしらえ

切り出した結果は手元に保存しない。各ステップの実行時に、元の出どころから Range 要求で必要な行と列だけを読み、DuckDB のインメモリ DB で扱う。
何度も読むと遅いものは、OS の一時ディレクトリ (`/tmp/study-geoai/`) にキャッシュする。キャッシュの名前には出どころの版を入れる。

Range 要求で部分読みできない出どころ (Ookla の元のバケット、国土数値情報の zip、GTFS の zip) は、一度だけ取得して z.yuiseki.net/static/ に Range で読める形 (または版を固定した形) で置き、そこから読む。どれもライセンスが再配布を認めていることを確かめてある。

範囲は `study_geoai.aoi.load("taito")` と `load("tokyo23")` で取る。境界と人口は jp-admin-2026-09 をコミットで固定して読む (初回 25 秒、キャッシュ後 1 秒未満)。

使う出どころ:

| 切り出すもの | 出どころ | 単位 |
|---|---|---|
| 小地域の境界と人口・世帯 | [estat-boundary-2020](datasets/huggingface-yuiseki/estat-boundary-2020.md) | 町丁目 (小地域) |
| 区の境界 | [jp-admin-2026-09](datasets/huggingface-yuiseki/jp-admin-2026-09.md) | 区 |
| 建物、POI、道路 | [Overture Maps](datasets/stac/overture-maps.md) の buildings、places、transportation | 地物 |
| 道路網 (もう 1 つの経路) | [osm-tokyo23-src-2026-08](datasets/huggingface-yuiseki/osm-tokyo23-src-2026-08.md) の `line` 表 | 地物 |
| 街路の状態 (電柱、街灯、歩道など) | [みちよみ](datasets/michiyomi/README.md) の区ごとの Parquet | シーン |
| 人口グリッド | [WorldPop](datasets/stac/worldpop.md) の JPN 100m | 100m 画素 |
| 通信速度 | [Ookla Speedtest](datasets/ookla-speedtest/README.md) の mobile | ズーム 16 のタイル |
| 施設、浸水想定、将来人口 | [mlit-nlftp](datasets/stac/mlit-nlftp.md) の P04 医療機関、P29 学校、A31a 洪水浸水想定、mesh500r6 | 地物、メッシュ |
| 区の施設一覧 | [tokyo-ckan](datasets/stac/tokyo-ckan.md) の組織 t131067 (台東区) と共通項目 | 施設 |
| バスの時刻表 | [台東区めぐりん GTFS](datasets/odpt-taito-megurin/README.md) | 便 |

下ごしらえで気をつけること (調査で見つかったもの):

- estat-boundary-2020 の `KEY_CODE` は一意ではない。PREF + CITY + S_AREA で 11 桁のキーを作り直す。
- osm-tokyo23-src の `roads` 表は道路網ではない。道路網には `line` 表の highway がある行を使う。
- WorldPop は Range 要求が効かないので、JPN 100m (約 104MB) を丸ごと落としてから切り出す。
- みちよみの `analysis` は VLM の推定。`confidence` で絞ってから使う。
- ライセンスはデータごとに違う。Ookla は CC BY-NC-SA 4.0 (非営利)、みちよみは CC BY-SA 4.0 (Mapillary のロゴ表示が要る)、Overture の buildings は ODbL。学習用途なら問題ないが、結果を公開するときは確かめる。

分析の共通の単位は、次の 2 つを使い分ける。

- 小地域 (町丁目): 人口がそのまま付いている。面積がばらばら。
- 250m 格子: みちよみの `cell_250m` と揃う。面積が一定。

## ステップごとの題材

### 1. 線形回帰 / ロジスティック回帰

- A: 小地域ごとに、人口密度を建物の数と延べ面積、POI の数から線形回帰で予測する。係数と残差の地図を見て、外れる町丁目 (上野公園、商業地など) を目で確かめる。
- A: みちよみのシーンで、架空線か地中化か (`undergrounded`) を、車道の幅、歩道の有無、緑の割合からロジスティック回帰で予測する。
- B: 同じ式を 23 区で当てはめ、係数が台東区と比べてどれだけ動くかを見る。
- 身につけたい感覚: 係数の意味、正則化 (Ridge / Lasso) で係数がどう縮むか、密度の偏りによるバイアス。

### 2. Decision Tree / Random Forest

- A: 1 番と同じ 2 つの課題を木で解く。深さを変えて、学習データでは当たるのに検証で外れる (過学習) 様子を、データの小さい台東区ではっきり見る。
- B: Random Forest で 23 区を解き、線形回帰で拾えなかった相互作用 (例: 車道が広く、かつ緑が多いと地中化されやすい) が出るかを見る。

### 3. Gradient Boosting / XGBoost

- B を主にする: Ookla の mobile タイルの下り速度 (`avg_d_kbps`) を、タイル内の人口、建物、POI、みちよみの集計 (電柱の数など) から予測する。
- `tests` (測定回数) の少ないタイルはばらつきが大きいので、重みを付けるかどうかも比べる。
- A: 台東区にかかるタイルだけで結果を地図に出し、目で確かめる。
- 比べるもの: scikit-learn の GradientBoosting、XGBoost、LightGBM、CatBoost。

### 4. Cross Validation とデータリーク

このカリキュラムの中心。A と B をつなぐ。

- みちよみの 23 区は、同じ地点に複数年のシーンがある。ランダムな KFold だと同じ場所が train と test の両方に入る。
- 次の 4 つの分け方で、1〜3 番のモデルの点数がどう変わるかを比べる。
  1. ランダムな KFold
  2. GroupKFold (groups = `cell_250m`)
  3. 空間ブロック CV (verde の BlockKFold、または GroupKFold に格子の番号を渡す)
  4. 区ごとに 1 つを抜く (22 区で学習して、残りの 1 区で試す)。抜く区が台東区のときの点数を、A の結果と並べる
- 時間のリーク: 撮影年で分け (例: 2020 年以前で学習、それ以降で試す)、ランダム分割と比べる。
- 身につけたい感覚: ランダム分割の点数は楽観的になる。どの分け方が「実際に使う場面」に合うかを、先に決めておく。

### 5. k-means / DBSCAN

- A: 台東区の電柱と街灯 (みちよみの `poles_visible`、`lights_road` があるシーン) と、Overture の places の点をクラスタリングする。k-means と DBSCAN で、地図上のまとまり方がどう違うかを見る。
- B: 同じ `eps` の DBSCAN を 23 区に当てると、密な区と疎な区で結果がどう崩れるかを見る。HDBSCAN (scikit-learn に入っている) と比べる。

### 6. PCA

- A: 250m 格子ごとに、みちよみの数値 (車道の幅、歩道の幅、電柱の数、緑の割合、色の鮮やかさ、標示の摩耗など) を集計し、PCA で 2 次元に縮める。第 1 主成分が何を表すかを、主成分得点の地図で確かめる。
- B: 23 区で同じことをし、区ごとに主成分得点の分布がどう違うかを見る。
- もう 1 つの題材: WorldPop の年齢性別の人口を格子ごとに並べ、年齢構成を PCA で縮める (年齢と性別がバンドで入っているか別ファイルかは未確認)。

### 7. Dijkstra / A*

- A: 台東区の道路網 (osm-tokyo23-src の `line` 表、または Overture の segment と connector) からグラフを作る。各小地域の中心から、いちばん近い医療機関 (P04) や避難所 (tokyo-ckan) までの最短経路を Dijkstra で求める。
- A: 直線距離をヒューリスティックにした A* と、展開したノードの数を比べる。
- B: 23 区のグラフで同じことをし、グラフが大きくなったときの速さの差を見る。
- もう 1 つの題材: めぐりんの停車時刻から時刻付きのグラフを作り、乗り換えを含めた最短時間を探す。
- 実施 (2026-09-29): 台東区の Dijkstra (`src/007-A-dijkstra`) と A* (`src/007-B-a-star`) で終えた。このカリキュラムの目的はアルゴリズムを一通り押さえることなので、23 区への拡大、一方通行、道路網どうしの比較 (N13、OSM、Overture)、道の快適さや浸水を重みにする経路、時刻表つきのグラフは、案として残して行っていない。

### 8. LP / MILP

- A: 最大被覆の配置問題。候補地 (電柱、街灯、公共施設) から k 個を選び、半径 300〜500m で覆える人口 (小地域の人口) を最大にする。
- 同じ問題を、LP として緩めた解と MILP の整数解で比べ、差 (整数性のギャップ) を見る。ソルバは HiGHS (highspy) と OR-Tools。
- B: 23 区に広げ、候補地の数が増えると MILP の解く時間がどう伸びるかを測る。

### 9. assignment / facility location

- A: 基地局の候補地の評価。需要を「人口 × 通信の遅さ (Ookla)」として、候補地 (電柱、街灯) から p 個を選ぶ p-median 問題を解く。
- A: 割当問題。小地域の住民を、いちばん近い避難所に割り当てる。避難所に収容人数の列があれば、容量つきにする (tokyo-ckan の列は未確認)。
- B: 23 区で同じ問題を解き、区の境界をまたいだ割当を許すかどうかで結果がどう変わるかを見る。

### 10. CP-SAT / scheduling

- A を主にする: めぐりんの 290 便は `block_id` がすべて空で、どの車両がどの便を走るかが書かれていない。便の始発と終着の時刻と停留所から、最少の車両で全便を回す割当 (vehicle scheduling) を CP-SAT で解く。
- 休憩や最大乗務時間の制約を足し、乗務員の勤務表 (crew scheduling) に広げる。
- B: 都営バスの GTFS (55,846 便、CC BY 4.0、登録不要) も `block_id` が空。1 日分や 1 営業所分に絞り、同じ解き方がどこまで大きな問題に通用するかを見る。詳しくは [東京 23 区のバスの GTFS](datasets/tokyo-gtfs/README.md)。
- 小さい例: 荒川区 (34 便)、葛飾区 (57 便)、杉並区 (24 便)。答えを手で確かめられる大きさなので、最初に解く。

### 11. SHAP / calibration

- B: 3 番の速度予測のモデルを SHAP で説明し、どの特徴量が効いているかを見る。A の台東区のタイルについては、1 件ずつの説明を地図と並べる。
- A と B: 1 番のロジスティック回帰 (地中化かどうか) と、2〜3 番の木のモデルの確率を較正曲線で比べ、どちらが「確率として信用できるか」を見る。
- みちよみの `confidence` (VLM の自己申告) が、実際の当たり方とどれだけ合っているかも、較正の題材になる。

### 12. 多目的最適化

- A: 8〜9 番の配置問題に、目的を 3 つ与える。覆える人口を多く、置く数 (費用) を少なく、洪水浸水想定区域 (A31a) の中を避ける。
- 重み付き和で解き、重みを振って Pareto frontier を描く。ε 制約法でも解き、重み付き和では出てこない解があるかを見る。
- B: 23 区で同じことをし、区ごとに Pareto frontier の形がどう違うかを見る。

## src/ との対応

`src/` の各ディレクトリ (`001-A-linear-regression` など) に、上のステップのコードを置く。
ディレクトリ名の A、B はステップの中の手法の順番で、このページの A (台東区)、B (23 区) とは別物。
